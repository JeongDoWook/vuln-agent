## 커넥터 13종 카탈로그 (코드와 1:1)

`VG_CONNECTOR_TYPES` 를 그대로 옮긴 표다. **UI 라벨·전송 방식·설정 필드는 코드가 정한다** —
여기와 다르면 코드가 맞다(화면의 커넥터 폼과 `tests/e2e` 가 같은 카탈로그를 본다).

| 타입 | UI 라벨 | 전송 | 설정 필드 | 받는 것 |
|---|---|---|---|---|
| `kev` | CISA KEV | file | `url` | 정적 JSON 파일 하나(`known_exploited_vulnerabilities.json`) |
| `osv` | OSV.dev | api | `url`·`ecosystem` | `querybatch` 에 패키지 목록 POST, 상세는 동시 8개 |
| `nvd` | NVD 2.0 | api | `url`·`api_key`·`days` | REST 를 `startIndex` 로 끝까지. 수정일 기준이라 범위 최대 120일 |
| `kisa` | KISA 보안공지 | feed | `url` | RSS(비우면 기본 3종 순회) + 상세 HTML 본문 |
| `epss` | FIRST EPSS | file | `url` | gz 덤프(`epss_scores-current.csv.gz`) |
| `debtracker` | 데비안 보안 트래커 | file | `url` | 릴리스별 debsecan 덤프(zlib). 릴리스는 수집된 호스트에서 자동 |
| `rhoval` | RHEL OVAL | file | **없음** | OVAL XML(Red Hat·Oracle bz2 / Alma 평문). 주소·릴리스 모두 코드가 정한다 |
| `rhunfixed` | Red Hat 미수정 | api | **없음** | hydra REST 를 동시 6개. 대상 컴포넌트는 수집된 호스트에서 자동 |
| `ubuntuoval` | Ubuntu OVAL | file | `url` | 릴리스별 OVAL(`*.xml.bz2`). `{C}` 자리에 코드네임이 들어간다 |
| `kcve` | 커널 CNA | file | `url` | kernel.org vulns.git 스냅샷 tarball(약 20MB) |
| `ssg` | SCAP 기준 | hybrid | `url` | GitHub 릴리스 API 로 자산 주소를 받고 그 tar.bz2 를 내려받는 **두 단계** |
| `pkgregistry` | 패키지 레지스트리 메타데이터 | api | **없음** | Packagist/npm/PyPI/Maven Central 에서 부모 패키지의 상위 버전이 자식을 어떤 제약으로 요구하는지 수집. 대상은 수집된 의존성 그래프에서 자동으로 정한다 |
| `generic_api` | 사용자 API | api | **없음**(주소·헤더·페이징·매핑을 UI 에서 정의) | 사용자가 지정하는 REST API |

> `fields` 가 비어 있는 넷(`rhoval`·`rhunfixed`·`pkgregistry`·`generic_api`)은 이유가 서로 다르다.
> 앞의 셋은 **코드와 수집된 호스트(또는 의존성 그래프)가 대상을 정하므로 사람이 채울 값이 없고**,
> `generic_api` 는 반대로 고정 필드로는 표현이 안 돼 전용 매핑 UI 를 따로 갖는다.

vuln-agent 는 서로 다른 성격의 취약점 정보원을 **역할별로** 조합한다.
하나의 소스로는 "이 취약점이 우리에게 얼마나 위험한가"를 답할 수 없기 때문이다.
각 커넥터는 아래의 서로 다른 질문에 답한다.

| 소스 | 답하는 질문 | 성격 | 우리 쓰임 |
|---|---|---|---|
| **NVD / OSV** | "이 취약점이 **무엇인가**" | 원본 정보 + 심각도(CVSS) + 영향 버전 | 취약점의 정체·설명·CVSS·영향 패키지의 기준 |
| **EPSS** | "**악용될 확률**이 얼마인가" | 예측(향후 30일 악용 확률 0~1) | 같은 등급 안에서 우선순위 정렬 |
| **CISA KEV** | "**실제로 악용되고 있는가**" | 확정된 사실(실측 악용 목록) | 등급 상향의 결정타 — 외부노출 + KEV = CRITICAL |
| **KISA** | "**한국 맥락**에서 챙길 게 있나" | 지역 보완(보호나라 국내 보안공지) | 해외 스캐너가 다루지 않는 국내 특화 정보 |
| **데비안 보안 트래커** | "이 데비안 빌드가 **아직도 취약한가**" · "**고칠 수는 있나**" | 배포판 벤더의 판정 | **백포트 오탐 제거** + 수정본이 아직 안 나온 건 `조치 불가` 로 분리 |
| **RHEL 계열 벤더 권고(OVAL)** | "이 CVE 는 **어느 EVR 에서 고쳐졌나**" | 배포판 벤더의 판정 | RHEL·Alma·**Oracle** 의 백포트 판정 + **취약 후보의 유일한 소스**(OSV 엔 이 배포판 데이터가 없다) |
| **Red Hat 미수정 CVE** | "벤더가 **고칠 생각이 있는가**" | 벤더의 조치 상태 | OVAL 엔 수정본만 있다 → **패치가 없는 취약점**을 "조치 불가" 로 표시 |
| **우분투 보안 OVAL** | "우분투가 **고쳤나 / 고칠 수는 있나**" | 배포판 벤더의 판정 | 백포트 오탐 제거 + 아직 수정본이 없는 건 `조치 불가` 로 분리 |
| **리눅스 커널 CNA** | "이 **커널 버전**에 수정본이 들어 있나" | 업스트림(kernel.org)의 판정 | 커널 CVE 판정 — 배포판 밖의 커널(라즈베리·자체빌드)까지 |
| **SCAP Security Guide** | "이 **설정**이 어느 기준에 어긋나나" | 검증된 보안설정 룰셋(오픈소스) | 보안설정 점검(CCE)의 **룰 정체·근거·기준 매핑**(CIS·NIST·STIG) |
| **패키지 레지스트리 메타데이터**(pkgregistry) | "부모를 올리면 자식은 **어느 버전**을 요구하게 되나" | 업스트림 레지스트리(Packagist/npm/PyPI/Maven Central)의 사실 | 전이 의존성 조치 문구가 "부모를 올려라"까지만 가고 목표 버전을 못 주던 빈 칸을 채우는 **수집 전용 데이터**(`tb_package_registry_meta`) |
| **범용 API 커넥터**(generic_api) | "고정 12종이 못 다루는 소스는?" | 사용자가 UI 에서 직접 등록하는 임의 REST API | 조직별 커스텀 소스(내부 취약점 DB, 자체 벤더 권고 등)를 role(identity/priority/vendor)별 매핑으로 upsert |

> 외부 피드로 다 못 거르는 백포트는 **호스트 자신이 답을 갖고 있다** — 에이전트가 보낸
> 패키지 changelog 의 CVE 수정 기록으로 2차 억제를 한다(피드가 아니라 수집물이 근거).
> 상세: [`architecture.md` §2](architecture.md#2-매처-판정-로직--실제로-위험한가).

## 보안설정 점검(CCE)은 왜 SSG 에 묶나

CVE 는 "취약한 버전" 이지만 CCE 는 "잘못된 설정" 이라, **무엇이 잘못인지**의 근거가 따로 필요하다.
MITRE CCE 사전은 2013년경 갱신이 끊겼고 KISA 가이드는 PDF/HWP 로만 나와서(API 없음) 그동안 룰을
`cce.php` 에 직접 써 넣었다. SSG(ComplianceAsCode)는 오픈소스 룰셋이고 룰마다 **CIS 벤치마크·
NIST 800-53·STIG·PCI-DSS 참조**와 근거(rationale)를 갖는다. 그 카탈로그를 받아 우리 점검을 룰 ID 에
묶었고(**39개 중 31개**, 매핑 정본은 `vg_cce_ssg_map()`), 화면이 "CIS 5.2.11 · NIST AC-17(a)" 처럼
**검증된 기준을 인용**한다.

**솔직한 한계**: 판정 로직(OVAL)까지 중앙에서 돌리진 못한다 — OVAL 은 살아 있는 파일시스템을
프로브하는데 우리는 에이전트가 보낸 사실만 갖고 있고 대상 서버엔 아무것도 설치하지 않는다.
그래서 룰의 **정체·근거·기준**은 SSG 가 갖고, **판정**은 수집값으로 우리가 한다. 대응 룰이 없는
8개 항목은 "자체 기준"으로 화면에 그대로 드러낸다 — ID 를 실제로 대조하지 않은 매핑은 적지 않는다.
그 8개를 왜 못 묶는지는 전수 대조(#519)로 확인해 `vg_cce_ssg_map()` 주석에 항목별로 적어 두었다.

## 판정은 왜 벤더·업스트림 소스의 몫인가

배포판(데비안·RHEL)은 **버전을 안 올리고 패치만 백포트**한다. 업스트림 버전만 보면 이미 고쳐진 것도
취약해 보인다 — 오탐 1순위였다(실측: HIGH 160건 중 73건). 그 판정은 **벤더만 할 수 있어서**
중앙이 벤더 데이터를 직접 받는다(에이전트는 사실만 수집한다 — 폐쇄망 서버엔 설치조차 못 한다).

**조치 가능 여부도 벤더가 답한다.** 데비안 트래커는 CVE 마다 "이 릴리스에 수정본이 나왔는가"
(debsecan `flags[3]=='F'`)를 준다. 실측(raspberrypi5-00): 트래커가 답한 1,025건 중 **708건이 수정본
없음**이었고, HIGH 87건 중 지금 `apt upgrade` 로 고칠 수 있는 건 8건뿐인데 화면엔 다 섞여 있었다.
이제 나머지는 `조치 불가` 로 분리한다. 우분투는 한 파일이 둘 다 준다 — 릴리스별 CVE OVAL 의 테스트에
조치 EVR(state)이 있으면 "그 버전 미만이 취약", 없으면 "그 패키지가 있으면 취약"(= 아직 수정본 없음).
RHEL 은 OVAL(수정본) + 미수정 CVE API(`rhunfixed`)로 나뉜다.

반대 방향의 함정도 있다. OVAL·트래커는 **고쳐진 것만** 담아서, 벤더가 "안 고친다/아직 안 고쳤다"고
표시한 CVE 는 통째로 안 보였다(실측 UBI8: Trivy 523건 중 514건). 이건 오탐이 아니라 미탐이고
**패치가 존재하지 않는** 종류다 — 등급은 그대로 두되 `조치 불가` 로 표시해 "지금 고칠 수 있는 것"과
분리한다. 섞으면 조치 불가 수백 건이 고칠 수 있는 몇 건을 덮는다.

**커널만은 배포판이 아니라 업스트림이 판정한다.** 라즈베리파이 OS 의 커널은
`linux-image-6.18.34+rpt-rpi-2712`(출처: Raspberry Pi Foundation)라 데비안 트래커에도 배포판
조치안(EVR)에도 없고, 매처는 서드파티 저장소 패키지를 "자동 판정 불가" 로 남기므로(그렇게 안 하면
진짜 취약점을 숨긴다) 커널 CVE 가 통째로 살아남았다 — 실측 raspberrypi5-00: **LOW 2,069건 중
702건이 커널 하나**였고, 6.18 커널에 CVE-2004-0230(2004년 TCP 이슈)까지 붙어 있었다.
2024년부터 **커널 팀이 직접 CVE 를 발행하므로**(kernel.org CNA) 레코드의 스트림별 수정 버전을
`uname -r` 로 잡은 **구동 커널의 업스트림 버전**(6.18.34)과 대조한다.

```
{"version":"6.5",   "status":"affected"}                                  ← 6.5 부터 취약
{"version":"6.1.78","lessThanOrEqual":"6.1.*","status":"unaffected"}      ← 6.1.y 는 6.1.78 에서 수정
{"version":"6.8",   "lessThanOrEqual":"*",    "status":"unaffected"}      ← 메인라인 6.8 에서 수정
```

**억제 방향으로만** 쓴다 — 내 스트림(6.18.y)에 수정본이 없으면 다른 스트림에서 고쳐졌다는 사실은
나와 무관하다. **배포판 커널엔 적용하지 않는다**(백포트를 쌓은 버전이라 업스트림 번호가 코드 내용을
대변하지 않는다 — 그쪽은 트래커·OVAL 이 이미 정확히 판정한다).

## 우선순위에 어떻게 반영되나

```
기본 심각도(CVSS, NVD/OSV)
  + 런타임 노출 맥락(외부노출 / 로컬리스닝 / 실행중 …)
  + KEV 등재 여부(실제 악용) → 한 단계 상향
  + EPSS(악용확률) → 같은 등급 내 정렬
= 최종 우선순위
```

등급 산식과 런타임 7단계의 정본은 [`architecture.md` §2.1](architecture.md#21-런타임-노출-7단계) 이다.

  아예 없으므로 `bin/backfill_kisa.php` 로만 채울 수 있다.

  두지 않는다. 키가 있으면 요청 제한이 완화된다(없어도 동작, 느릴 뿐).
