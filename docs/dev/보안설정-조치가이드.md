# 보안설정(CCE) 조치 가이드

> 문서 기준: 2026-08-20 · 점검 39종.
> 정본 코드는 `server/src/cce.php`(진입점) → `server/src/cce/checks/`(판정 5종) ·
> `server/src/cce/catalog.php`(목록 + SSG 룰 매핑, `vg_cce_rules()`).

## 이 문서는 무엇인가

`/control.php`(통제 상세) 화면은 통제 하나를 열었을 때 **"무엇을 요구하나"** 와
**"어떻게 고치나"** 를 한 줄씩만 보여준다. 표 안에서 읽히도록 짧게 줄인 것이고,
그 자리에 원래 들어 있던 **긴 원문이 이 문서다.**

| | 어디 | 무엇 |
|---|---|---|
| 요약 | 화면(DB `tb_control_guide.description` · `tb_cce_rule_guide.summary`/`remediation`) | 목록을 훑으며 무엇이 문제인지 파악하는 용도 |
| 절차 | 이 문서 | 실제로 서버에 붙어 고칠 때 필요한 예시 명령·주의사항·검증 방법 |

**근거 원칙은 시드 마이그레이션(`db/migrations/20260809093626_control_guide.sql`)과 같다 —
지어내지 않는다.** 룰별 조치는 전부 **실제 판정 로직**(`server/src/cce/checks/`)에서 끌어냈다.
무슨 파일의 무슨 지시어를 보는지, 임계값이 얼마인지가 코드와 일치한다.
통제 설명은 `tb_control_mapping.control_name` 이 말하는 범위와, 그 통제에 실제로 걸린 점검이
보는 대상 안에서만 쓴다 — 조문 번호·원문을 새로 짓지 않는다.

판정 로직·임계값을 바꾸면 이 문서도 함께 고친다. 고쳐도 FAIL 이 사라지지 않는 안내는
없느니만 못하다.

### KISA U-코드와의 관계

아래 표의 `U-코드` 열은 **`tb_control_mapping`(`framework='KISA_U'`)이 정본이다.**
점검 제목·코드 주석에도 `(U-xx)` 가 붙어 있지만(#662) 그건 표기일 뿐이라 정본이 아니다 —
실제로 `CCE-ACC-UID0` 은 주석이 "U-02 계열"이라 적었는데 매핑은 **U-44** 이고,
`CCE-SSH-ROOT`·`CCE-SVC-LEGACY` 는 제목에 코드가 아예 없다. 화면 `/kisa-u.php` 도 같은 표를 본다.
대조는 이 한 줄로 한다:

```sql
select rule_code, group_concat(control_id order by control_id separator ',')
  from tb_control_mapping where framework='KISA_U' and is_deleted=0
 group by rule_code order by rule_code;
```

**매핑은 1:1 이 아니다.** 한 점검이 여러 U-코드에 걸리고(`CCE-SVC-LEGACY` → U-19·U-21),
한 U-코드가 여러 점검에 걸린다(U-54 → `CCE-SESSION-TMOUT`·`CCE-SSH-IDLE`). 그래서 `U-코드`
열은 **콤마로 여러 값을 적는다** — 칸을 하나로 제한하면 앞의 경우를 적을 수 없고, 행을 쪼개면
표의 룰 코드 오름차순이 깨진다. 1:1 로 되돌리지 않는다.

빈 칸은 대응 U-코드가 없다는 뜻이지 점검이 약하다는 뜻이 아니다. SSH 세부 5종
(`vg_cce_check_ssh_hardening`) 중 `CCE-SSH-IDLE` 만 자기 코드(U-54)를 갖고 나머지 4종은
U-01 요구를 잘게 나눈 것이며, 파일 권한 9종 중 6종이 U-07~U-12 에 대응하고
`CCE-FILE-CRONTAB`·`CCE-FILE-GROUP`·`CCE-FILE-GSHADOW` 는 대응 코드가 없다.

**분모는 이 39종이 아니다.** `/kisa-u.php` 는 「주요정보통신기반시설 기술적 취약점 분석·평가
방법 상세가이드」 UNIX 서버 **72개 전체**를 `tb_control_catalog` 로 세워 두고, 우리가 덮는
항목과 **비어 있는 항목까지** 함께 센다(#651). 즉 이 문서는 "덮는 쪽"의 조치 절차이고,
"얼마나 덮나"는 그 화면이 답한다.

## 1. 점검 항목(CCE)별 조치

룰 코드 오름차순. `sshd` 항목의 판정 근거는 `sshd -T` **실효값**이므로, 조치 후 확인도 같은
명령으로 한다(`sshd -T | grep <지시어>`). 여러 줄이 필요한 설정 예시는 [§1-1](#1-1-설정-예시)에 모았다.

| 룰 코드 | U-코드 | 무엇을 보는가(위반 조건) | 조치 |
|---|---|---|---|
| `CCE-ACC-DUPUID` | U-52 | 서로 다른 계정이 같은 UID 를 쓴다 | `cut -d: -f3 /etc/passwd \| sort \| uniq -d` 로 겹친 UID 를 찾는다. 남길 계정을 정한 뒤 나머지는 `usermod -u` 로 바꾸고, 그 계정이 소유하던 파일은 `find / -uid <옛 UID> -exec chown` 으로 함께 옮긴다 |
| `CCE-ACC-EMPTYPW` | | 패스워드가 비어 인증 없이 로그인되는 계정이 있다 | `awk -F: '$2==""' /etc/shadow` 로 확인. 쓰는 계정이면 `passwd <계정>`, 안 쓰면 `passwd -l <계정>` 또는 `usermod -s /usr/sbin/nologin` |
| `CCE-ACC-SHADOW` | U-04 | `/etc/passwd` 의 패스워드 칸에 해시가 남아 있다 | `pwconv` 로 `/etc/shadow` 이전(두 번째 칸이 `x` 가 된다). 그룹 쪽은 `grpconv`. 이전 뒤 `/etc/shadow` 권한을 `CCE-FILE-SHADOW` 기준으로 확인 |
| `CCE-ACC-UID0` | U-44 | root 외에 UID 0 인 계정이 있다 | `awk -F: '$3==0 {print $1}' /etc/passwd` 로 확인 후 `usermod -u <새 UID>` 또는 삭제. 관리 목적이면 별도 계정 + sudo 로 대체한다 — UID 0 은 이름과 무관하게 커널이 root 로 취급한다 |
| `CCE-CRYPTO-DISK` | | LUKS 볼륨이 없다 → **정보성(판정 불가)** | 위반으로 판정하지 않는다. 다만 개인정보·기밀 저장 서버라면 저장 데이터 암호화를 별도 검토한다(신규 구축 시 설치 단계 LUKS 가 이후 전환보다 훨씬 간단하다) |
| `CCE-CRYPTO-KCMVP` | | SSH 알고리즘에 ARIA/SEED 계열이 있는지 **정보로만** 남긴다 | 이 도구로는 조치 여부를 확인할 수 없다. 검증필 암호모듈 요건은 "어떤 알고리즘"이 아니라 "쓰는 모듈이 검증을 받았는가"라 별도 문서로 확인한다 |
| `CCE-CRYPTO-SSH-CIPHER` | | sshd 의 `Ciphers`·`MACs`·`KexAlgorithms` 에 CBC·MD5·SHA1·64비트 UMAC 계열이 남아 있다 | 허용 목록을 명시한다([§1-1](#1-1-설정-예시)). OpenSSH 기본 `MACs` 에 `hmac-sha1`·`umac-64` 가 있어 손대지 않은 서버는 대부분 위반 — **명시 설정이 곧 조치다.** 오래된 클라이언트 접속 가능 여부를 먼저 확인한다 |
| `CCE-FILE-CRONTAB` | | `/etc/crontab` 소유자≠root 이거나 권한이 640 보다 느슨하다 | `chown root:root /etc/crontab && chmod 640 /etc/crontab`. `/etc/cron.d/`·`/etc/cron.*/` 도 함께 확인. 파일이 없는 환경(일부 컨테이너)은 판정 불가(NA) |
| `CCE-FILE-GROUP` | | `/etc/group` 소유자≠root 이거나 644 보다 느슨하다 | `chown root:root /etc/group && chmod 644 /etc/group`. 쓰기가 열리면 임의 계정을 `wheel`·`sudo` 특권 그룹에 넣을 수 있다 |
| `CCE-FILE-GSHADOW` | | `/etc/gshadow` 소유자≠root 이거나 400 보다 느슨하다 | `chown root:root /etc/gshadow && chmod 400 /etc/gshadow`. 그룹 패스워드 해시가 담기므로 shadow 와 같은 수준으로 보호한다 |
| `CCE-FILE-HOSTS` | U-09 | `/etc/hosts` 소유자≠root 이거나 600 보다 느슨하다 | `chown root:root /etc/hosts && chmod 600 /etc/hosts`. 배포판 기본이 644 라 대부분 위반으로 잡히는데 **오탐이 아니라 기준(600)과 기본값이 다른 것이다** — 완화하지 않는다. 좁힌 뒤 이름 해석 영향을 확인한다 |
| `CCE-FILE-PASSWD` | U-07 | `/etc/passwd` 소유자≠root 이거나 644 보다 느슨하다 | `chown root:root /etc/passwd && chmod 644 /etc/passwd`. 읽기는 계정 조회에 필요하지만 쓰기는 root 만이면 된다 |
| `CCE-FILE-SERVICES` | U-12 | `/etc/services` 소유자≠root 이거나 644 보다 느슨하다 | `chown root:root /etc/services && chmod 644 /etc/services` |
| `CCE-FILE-SHADOW` | U-08 | `/etc/shadow` 소유자≠root 이거나 400 보다 느슨하다 | `chown root:root /etc/shadow && chmod 400 /etc/shadow`(배포판에 따라 그룹 `shadow` 인 0640 관례가 있으나 이 점검은 400 이하 기준). 좁힌 뒤 `passwd` 변경이 되는지 확인 |
| `CCE-FILE-SYSLOG` | U-11 | `/etc/rsyslog.conf` 소유자≠root 이거나 640 보다 느슨하다 | `chown root:root /etc/rsyslog.conf && chmod 640 /etc/rsyslog.conf`, `/etc/rsyslog.d/` 도 같이. 로그 설정이 바뀌면 침해 흔적이 애초에 안 남는다 |
| `CCE-FILE-XINETD` | U-10 | `/etc/xinetd.conf` 소유자≠root 이거나 600 보다 느슨하다 | 안 쓰면 패키지째 제거가 가장 확실하다(그 경우 판정 불가로 남는다). 계속 쓰면 `chown root:root /etc/xinetd.conf && chmod 600 /etc/xinetd.conf` + `/etc/xinetd.d/` 확인 |
| `CCE-LOG-REMOTE` | | rsyslog 에 원격 전송 설정이 없다 | `/etc/rsyslog.d/` 에 전송 규칙 추가([§1-1](#1-1-설정-예시)). `rsyslogd -N1` 로 문법 확인 후 재시작하고, 수집 서버에 실제로 도착하는지 본다 |
| `CCE-LOG-RETENTION` | | 저널·logrotate 어느 쪽으로 계산해도 보존기간이 **90일 미만**이다 | 둘 중 긴 쪽이 기준을 넘으면 통과다([§1-1](#1-1-설정-예시)). 늘리기 전에 `/var/log` 여유 공간을 먼저 확인한다 |
| `CCE-PW-LOCKOUT` | U-03 | PAM 설정에 `pam_faillock`·`pam_tally2` 가 없다 | `pam_faillock` 을 auth 스택에 넣고 `/etc/security/faillock.conf` 에서 `deny`·`unlock_time` 을 정한다(RHEL 은 `authselect enable-feature with-faillock`). 일부러 실패시켜 `faillock --user <계정>` 으로 확인 — **모듈만 넣고 스택 순서가 틀리면 잠기지 않는다** |
| `CCE-PW-MAXDAYS` | U-47 | `/etc/login.defs` 의 `PASS_MAX_DAYS` 가 **90 초과이거나 0 이하(무제한)** | `PASS_MAX_DAYS 90`(이하) 설정. login.defs 는 **이후 생성 계정에만** 적용되므로 기존 계정은 `chage -M 90 <계정>`, 확인은 `chage -l <계정>` |
| `CCE-PW-MINDAYS` | U-48 | `PASS_MIN_DAYS` 가 **1 미만** | `PASS_MIN_DAYS 1`(이상) + 기존 계정 `chage -m 1 <계정>`. 최소 기간이 없으면 변경 직후 되돌려 주기 정책이 무력화된다 |
| `CCE-PW-MINLEN` | U-46 | `PASS_MIN_LEN` 이 **8 미만** | `PASS_MIN_LEN 8`(이상). 실제 강제는 PAM 이 하는 배포판이 많으므로 `/etc/security/pwquality.conf` 의 `minlen` 도 같은 값 이상으로 맞춘다 |
| `CCE-PW-QUALITY` | U-02 | PAM 설정에 `pam_pwquality`·`pam_cracklib` 이 없다 | 모듈 설치(`libpam-pwquality`/`libpwquality`) 후 패스워드 스택에 `pam_pwquality.so` 추가(데비안 `/etc/pam.d/common-password`, RHEL 은 `authselect`). 규칙은 `pwquality.conf` 의 `minlen`·`minclass`. 직접 편집보다 배포판 설정 도구가 업데이트 때 안 덮인다 |
| `CCE-RHOSTS` | U-17 | `/etc/hosts.equiv` 또는 홈의 `.rhosts` 가 있다 | `rm -f /etc/hosts.equiv`; `find /home /root -maxdepth 2 -name .rhosts -delete`. 패스워드 없는 신뢰 접속 선언이라 남길 이유가 없다. r 계열 서비스는 `CCE-SVC-LEGACY` 로 함께 확인 |
| `CCE-ROOT-PATH` | U-05 | root 의 PATH 에 현재 디렉터리(`.`)가 독립 경로로 있다 | `/root/.bash_profile`·`/root/.bashrc`·`/etc/profile` 의 PATH 정의에서 `.` 과 **빈 항목**(연속 콜론, 맨 앞·뒤 콜론)을 제거한다. **빈 항목도 현재 디렉터리로 해석되므로** 점만 지우면 남는다 |
| `CCE-SEC-FW` | | ufw·firewalld·nftables·iptables 어디에도 활성 정책이 없다 | 배포판이 쓰는 방화벽 하나를 골라 **기본 차단 + 필요한 포트만 허용**([§1-1](#1-1-설정-예시)). **원격 접속 포트를 먼저 허용한 뒤 활성화한다** |
| `CCE-SEC-MODULE` | | SELinux 가 Enforcing 도 아니고 AppArmor 프로파일도 적재돼 있지 않다 | RHEL: `/etc/selinux/config` 에 `SELINUX=enforcing` + `setenforce 1`(오래 Disabled 였다면 `touch /.autorelabel` 후 재부팅). 데비안: `systemctl enable --now apparmor` 후 `aa-status` 확인 |
| `CCE-SESSION-TMOUT` | U-54 | 셸의 `TMOUT` 이 **미설정이거나 600초 초과** | `/etc/profile` 또는 `/etc/profile.d/tmout.sh` 에 `TMOUT=600` + `export TMOUT`(변경을 막으려면 `readonly TMOUT`). 재접속 후 `echo $TMOUT` 확인. SSH 세션 쪽 유휴 종료는 `CCE-SSH-IDLE` 이 따로 본다 |
| `CCE-SSH-EMPTYPW` | | `PermitEmptyPasswords` 실효값이 yes | `PermitEmptyPasswords no` 후 재시작. 빈 패스워드 계정 자체는 `CCE-ACC-EMPTYPW` 와 함께 정리한다 |
| `CCE-SSH-GRACE` | | `LoginGraceTime` 이 **60초 초과** | `LoginGraceTime 60` 이하 후 재시작. 인증 미완료 연결이 오래 열려 있을수록 연결 슬롯 고갈에 노출된다 |
| `CCE-SSH-IDLE` | U-54 | `ClientAliveInterval` 이 **0(무제한)이거나 300초 초과** | `ClientAliveInterval 300` 이하 + `ClientAliveCountMax`(예: 300/2 → 무응답 약 10분 뒤 종료). **0 은 "끊지 않음"이라 설정돼 있어도 위반이다** |
| `CCE-SSH-MAXAUTH` | | `MaxAuthTries` 가 **5 초과** | `MaxAuthTries` 5 이하(예: 4) 후 재시작. 값이 클수록 한 연결에서 시도할 수 있는 인증 횟수가 늘어난다 |
| `CCE-SSH-PWAUTH` | | `PasswordAuthentication` 실효값이 yes | 공개키를 먼저 등록(`~/.ssh/authorized_keys`, 권한 600)한 뒤 `PasswordAuthentication no`. `KbdInteractiveAuthentication`(구 `ChallengeResponseAuthentication`)도 no 인지 확인 — 이쪽이 열려 있으면 패스워드 인증이 사실상 남는다 |
| `CCE-SSH-ROOT` | U-01 | `PermitRootLogin` 실효값이 yes | `PermitRootLogin no`(키 기반 root 작업이 꼭 필요하면 `prohibit-password`). `sshd_config.d/*.conf` 가 뒤에서 덮어쓰지 않는지 확인. **끊기지 않도록 일반 계정의 sudo 권한을 먼저 확보한 뒤 바꾼다** |
| `CCE-SSH-X11` | | `X11Forwarding` 실효값이 yes | GUI 전달이 필요 없으면 `X11Forwarding no`. 특정 사용자·그룹만 필요하면 `Match` 블록으로 범위를 좁힌다 |
| `CCE-SVC-LEGACY` | U-19, U-21 | telnet·rsh·rlogin·rexec·vsftpd·proftpd·tftp·finger·talk 중 활성인 것이 있다 | `systemctl disable --now <유닛>` 후 가능하면 패키지째 제거. xinetd 항목이면 `/etc/xinetd.d/` 의 해당 파일에 `disable = yes` 후 재시작. 원격 셸은 SSH, 파일 전송은 SFTP/SCP 로 대체 |
| `CCE-TIME-OFFSET` | | NTP 기준 시각 오차가 **1.0초 초과** | 동기화가 살아 있는지 먼저 확인(`chronyc sources -v`), 오차가 크면 `chronyc makestep`. 계속 벌어지면 상위 NTP 도달성·네트워크 지연·가상화 호스트 시계를 점검한다. 오차가 크면 여러 서버 로그를 시간순으로 맞출 수 없어 사고 분석이 무너진다 |
| `CCE-TIME-SYNC` | | NTP 동기화 상태가 확인되지 않는다 | `systemctl enable --now chronyd`(또는 systemd-timesyncd). `/etc/chrony.conf` 에 조직 NTP 서버 지정 후 `timedatectl` 의 "System clock synchronized: yes" 와 `chronyc tracking` 의 "Leap status: Normal" 로 확인. 폐쇄망이면 내부 시간 서버 + 123/udp |
| `CCE-UMASK` | U-56 | `/etc/login.defs` 의 `UMASK` 가 **022 보다 느슨하다** | `UMASK 022`(이상, 즉 더 엄격하게). 셸 초기화 파일(`/etc/profile`·`/etc/bashrc`)에서 더 느슨한 umask 를 다시 지정하고 있지 않은지 확인 — **나중에 실행되는 쪽이 최종값이 된다** |

### 1-1. 설정 예시

여러 줄이 필요한 것만 모았다. 나머지는 위 표의 조치 열이 한 줄로 끝난다.

**`CCE-CRYPTO-SSH-CIPHER`** — `/etc/ssh/sshd_config`

```
Ciphers aes256-gcm@openssh.com,aes128-gcm@openssh.com,aes256-ctr,aes128-ctr
MACs hmac-sha2-512-etm@openssh.com,hmac-sha2-256-etm@openssh.com
KexAlgorithms curve25519-sha256,curve25519-sha256@libssh.org,diffie-hellman-group16-sha512
```

재시작 후 `sshd -T | grep -E '^(ciphers|macs|kexalgorithms)'` 로 실효값을 확인한다.

**`CCE-LOG-REMOTE`** — `/etc/rsyslog.d/`

```
*.* @@로그서버:514      # @@ 는 TCP, @ 는 UDP
```

전송 중 유실을 줄이려면 `action(type="omfwd" …)` 형식으로 큐·재시도를 함께 지정한다.

**`CCE-LOG-RETENTION`** — 둘 중 긴 쪽이 90일을 넘으면 통과다.

- journald: `/etc/systemd/journald.conf` 에 `Storage=persistent` + `MaxRetentionSec=90d` 후
  `systemctl restart systemd-journald`.
- logrotate: `/etc/logrotate.conf` 의 주기 × `rotate` 값이 90일 이상이 되게 한다
  (예: `weekly` + `rotate 13`) 또는 `maxage 90` 을 명시한다.

**`CCE-SEC-FW`** — 하나만 고른다.

- ufw: `ufw default deny incoming` → `ufw allow <포트>` → `ufw enable`
- firewalld: `systemctl enable --now firewalld` 후
  `firewall-cmd --permanent --add-service=ssh --reload`
- nftables/iptables 직접 운용이면 정책을 저장해 재부팅 후에도 남게 한다.

## 2. 통제별 설명

화면의 "이 통제가 요구하는 것" 카드에는 아래 내용을 한두 문장으로 줄여 싣는다. 전문은 여기 있다.

### ISMS-P 인증기준

통제명(`tb_control_mapping.control_name`)이 말하는 범위 안에서, 이 통제에 실제로 매핑된 점검이 보는
대상만 설명한다.

| 통제 | 요구하는 것 |
|---|---|
| **2.5.3** | 사용자 인증 수단이 추측·자동화 공격에 견디도록 운영되어야 한다. 반복되는 로그인 실패를 그대로 허용하면 인증 자체가 시간을 들이면 뚫리는 관문이 된다. 이 화면은 로그인 실패 임계값과 계정 잠금 설정 여부로 증적을 본다 |
| **2.5.4** | 비밀번호의 생성·변경·보관 규칙을 정하고 시스템이 강제해야 한다. 길이·복잡도·사용기간이 설정으로 강제되지 않으면 규정 문서만 남고 실제 계정은 규칙 밖에 있게 된다. 해시는 일반 사용자가 읽을 수 없는 곳에 보관해야 한다 |
| **2.5.5** | 관리자 권한 계정과 특수 권한은 최소한으로 부여하고 식별 가능해야 한다. root 와 같은 권한을 가진 계정이 이름만 다르게 존재하거나 UID 가 겹치면, 권한 현황 파악도 행위 추적도 불가능하다 |
| **2.6.1** | 네트워크 접근은 필요한 경로만 허용하고 나머지는 차단해야 한다. 호스트에 방화벽 정책이 없으면 서버가 열어 둔 모든 포트가 그대로 접근 경로가 된다 |
| **2.6.3** | 응용프로그램·시스템 세션은 일정 시간 사용이 없으면 종료되어야 한다. 유휴 세션이 남아 있으면 인증 절차를 거치지 않은 사람이 이미 인증된 화면을 그대로 쓸 수 있다 |
| **2.6.6** | 원격 접근은 안전한 방식으로 제한해야 한다. 원격 관리 통로는 인터넷에 직접 노출되는 경우가 많아, 특권 계정 직접 로그인·약한 인증 수단·불필요한 기능이 열려 있으면 그대로 침입 경로가 된다 |
| **2.10.1** | 보안 관련 시스템 파일과 설정은 인가된 사용자만 변경할 수 있어야 한다. 계정·인증·로그·스케줄 관련 파일의 소유자와 권한이 느슨하면, 권한 상승과 흔적 제거가 별도의 취약점 없이도 가능해진다 |

### KISA U-코드

KISA 「주요정보통신기반시설 기술적 취약점 분석·평가 가이드」의 U-코드.
**전체 72개 중 아래 21개를 덮는다** — 나머지 51개와 커버리지는 `/kisa-u.php` 가 보여준다.

| 코드 | 요구하는 것 |
|---|---|
| **U-01** | root 로 원격 직접 로그인 금지. root 는 어느 서버에나 있는 이름이라 무차별 대입의 첫 표적이고, 직접 로그인이 열려 있으면 "누가 작업했는가"가 로그에 안 남는다. 일반 계정 접속 후 권한 상승 경로만 남긴다 |
| **U-02** | 패스워드 복잡성 규칙을 시스템이 강제한다. 교육·규정만으로는 지켜지지 않으므로 인증 모듈 수준에서 거부하게 설정한다 |
| **U-03** | 로그인 실패 일정 횟수 이상이면 계정 잠금. 임계값이 없으면 공격자가 시간 제한 없이 계속 시도할 수 있다. 잠금은 인증 모듈에서 처리해 모든 로그인 경로에 함께 적용되게 한다 |
| **U-04** | 패스워드 해시를 `/etc/passwd` 가 아닌 `/etc/shadow` 로 분리. passwd 는 계정 조회를 위해 전체 읽기가 필요하므로, 해시가 남아 있으면 일반 사용자도 오프라인 크래킹 재료를 가져간다 |
| **U-05** | root 홈·PATH 를 안전하게 유지. PATH 에 현재 디렉터리(`.`)가 있으면 작업 디렉터리에 심어 둔 동명 실행 파일이 정상 명령보다 먼저 실행된다 |
| **U-07** | `/etc/passwd` 소유자를 root 로 두고 쓰기 제한. 계정 목록·셸·UID 가 담긴 파일이라 쓰기가 열리면 임의 계정 추가와 UID 변조가 가능하다 |
| **U-08** | `/etc/shadow` 는 해시 원본이므로 root 만 읽을 수 있어야 한다. 읽기가 조금이라도 넓으면 해시가 유출돼 오프라인에서 무제한 크래킹된다 |
| **U-09** | `/etc/hosts` 소유자·권한 제한. DNS 보다 먼저 조회되므로 쓰기가 열리면 이름을 공격자 서버로 돌려 정상 통신을 가로챌 수 있다 |
| **U-10** | (x)inetd 설정 파일 소유자·권한 제한. 수정되면 임의 서비스를 슈퍼데몬에 등록해 원격 실행 경로를 만들 수 있다. 서비스를 안 쓰는 서버엔 파일 자체가 없는 것이 정상이다 |
| **U-11** | syslog(rsyslog) 설정 파일 소유자·권한 제한. 로그 설정이 수정되면 기록 대상·전송 경로가 바뀌어 침해 흔적이 애초에 안 남게 만들 수 있다 |
| **U-12** | `/etc/services` 소유자·권한 제한. 포트와 서비스 이름의 대응표라 변조되면 운영자와 점검 도구가 실제와 다른 서비스를 보게 된다 |
| **U-17** | `hosts.equiv`·`$HOME/.rhosts` 미사용. "이 호스트·계정은 믿는다"는 선언이라 남아 있으면 패스워드 없이 원격 접속이 성립한다 |
| **U-19** | Finger 비활성화. 계정·로그인 이력을 인증 없이 외부에 알려 주어 공격 대상 계정을 고르는 데 그대로 쓰인다 |
| **U-21** | rsh·rlogin·rexec 등 r 계열 비활성화. 인증과 데이터를 평문으로 주고받고 신뢰 파일 기반 접속을 허용하므로 SSH 로 대체한다 |
| **U-44** | root 외 계정이 UID 0 을 갖지 않게 한다. UID 0 이면 이름이 무엇이든 커널은 root 로 취급하므로 계정 하나만 추가하면 root 권한을 우회 취득할 수 있고 감사 추적도 흐려진다 |
| **U-46** | 패스워드 최소 길이 강제. 길이는 무차별 대입에 필요한 시간을 직접 결정하는 값이라, 짧으면 복잡성 규칙이 있어도 방어가 되지 않는다 |
| **U-47** | 패스워드 최대 사용기간. 만료가 없으면 유출된 패스워드가 발견될 때까지 무기한 유효하다 |
| **U-48** | 패스워드 최소 사용기간. 없으면 변경 직후 곧바로 예전 패스워드로 되돌려 이력 검사와 주기 변경을 무력화할 수 있다 |
| **U-52** | 동일 UID 공유 금지. UID 가 겹치면 파일 소유권과 로그가 계정을 구분하지 못해 "누가 했는가"를 사후에 특정할 수 없다 |
| **U-54** | 방치된 세션 자동 종료. 자리를 비운 터미널과 끊긴 원격 세션은 그대로 인증된 통로로 남는다 |
| **U-56** | 새 파일의 기본 권한(UMASK) 제한. 느슨하면 이후 생성되는 모든 파일이 그룹·타인에게 열린 채로 만들어져, 파일별로 고쳐도 계속 새 구멍이 생긴다 |

### N2SF(국가 망 보안체계)

`control_name` 은 리포트 표기를 그대로 쓴다 — 여기서도 영역이 다루는 성격만 적고 정식 명칭·조문을
새로 짓지 않는다.

| 영역 | 다루는 성격 |
|---|---|
| **AC** | 계정의 생성·식별·정리. 계정마다 유일한 식별자가 보장되어야 접근 이력과 파일 소유권이 사람과 이어진다 |
| **AP** | 인증 자격증명의 강도와 수명을 정책으로 강제. 패스워드 복잡도·최소 길이·사용기간과 해시 보관 위치가 증적이 된다 |
| **EB** | 외부와의 경계에서 트래픽 통제. 호스트 방화벽은 경계 장비가 놓치는 내부·측면 이동 경로를 막는 마지막 층이다 |
| **IN** | 시스템 내부 무결성. 계정·인증·로그·스케줄 설정 파일의 소유자·권한이 지켜져야 시스템이 스스로 보고하는 상태를 신뢰할 수 있다 |
| **LI** | 로그인 시도 자체의 통제. 실패 횟수 제한 없이 무한히 허용하면 다른 인증 정책이 아무리 강해도 시간 문제로 뚫린다 |
| **LP** | 최소권한. root 와 동일한 UID 를 가진 계정이나 여러 사람이 공유하는 UID 는 최소권한 원칙과 정면으로 어긋난다 |
| **LP-4** | 관리자 권한의 사용 경로 제한. 특권 계정으로 원격 직접 접속하는 통로가 열려 있으면 권한 제한과 행위 추적이 함께 무너진다 |
| **SN** | 세션의 유지와 종료. 사용하지 않는 세션은 정해진 시간 뒤 끊어 인증된 통로가 방치되지 않게 한다 |
