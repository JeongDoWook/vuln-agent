# 데이터베이스 — 테이블 레퍼런스

MySQL 8. 전 테이블 `tb_` 접두사 + 감사 4컬럼(`created_at`·`updated_at`·`is_deleted`·`deleted_at`) 통일.
소프트삭제는 `is_deleted=1`(물리 삭제 안 함). 스키마 변경은 `db/migrations/`(타임스탬프 파일명, 멱등),
`deploy/migrate.sh` 가 미적용분만 적용하고 `tb_schema_migrations` 에 기록한다.

- **관계도(ERD)** 는 `architecture.md §5` 에 있다 — 여기는 **테이블별 컬럼·책임** 레퍼런스다.
- 현재 34개 테이블(`tb_schema_migrations` 포함). PK 는 `[PRI]`, 유니크 `[UNI]`, 인덱스 `[MUL]` 로 표기.

## 1. 수집·인벤토리 — 에이전트가 보내온 원본

### tb_hosts — 모니터링 대상 서버
`id [PRI]`, `fqdn [UNI]`, `hostname`, `os_id`, `os_version`, `first_seen`, `last_seen`
- 호스트 1행. `fqdn` 이 자연키(유니크). 스캔이 쌓여도 호스트는 하나.

### tb_scans — 수집 1회분(시계열의 단위)
`id [PRI]`, `host_id [FK]`, `collected_at`, `agent_version`, `schedule`, `elapsed_seconds`, `peak_rss_mb`, `cpu_seconds`,
`os_id`, `os_version`, `kernel`, `running_kernel`, `kernel_latest`, `kernel_reboot_needed`, `cpe`,
`package_family`, `content_hash`, `package_count`, `exposure_count`, `raw_json`, `received_at`
- 한 호스트의 매 수집이 1행. 이 밑으로 packages/exposures/processes/findings 가 매달린다.
- `content_hash`: 내용이 바뀔 때만 새 스냅샷을 만드는 기준(PID 등 잡음 제외). 같은 내용 재전송은 새 행을 안 만든다.
- **os_id/kernel 등은 수집 시점 스냅샷** — 호스트의 현재값을 복제한 게 아니라 "그때 그랬다"는 시점 사실이라 정규화 대상 아님.
- `kernel_reboot_needed`: 커널 패치됐지만 옛 커널 실행 중 → 재부팅 필요 판정(매처가 씀).
- `schedule`: 에이전트의 수집 주기(systemd `OnCalendar` 값, 예 `hourly`/`daily`/`*:0/30`). 에이전트가 `meta.schedule` 로 실어 보내면 최신 스캔에 기록 — 중앙이 노드별 주기를 읽기전용으로 보여주기 위한 것.

### tb_packages — 설치 패키지
`id [PRI]`, `scan_id [FK]`, `container_id`, `manager`, `name [MUL]`, `version`, `arch`,
`source_pkg [MUL]`, `source_version`, `origin`, `vendor`
- `container_id`: 0=호스트, 양수=그 컨테이너 내부 패키지.
- `source_pkg`/`source_version`: 백포트·오탐 감소의 핵심(바이너리 아닌 소스패키지 단위 매칭).
- `origin`: 서드파티 저장소 판정(오억제 방지).

### tb_exposures — 리스닝 소켓(포트) = 런타임 노출
`id [PRI]`, `scan_id [FK]`, `container_id`, `pid`, `proc`, `proto`, `bind_addr`, `port`,
`scope [MUL]`, `exe_pkg [MUL]`, `loaded_pkgs`
- 차별점 ①(런타임 노출 상관)의 원천. `scope` = EXTERNAL/LOCAL/BOUND/FILTERED.
- `loaded_pkgs`: 그 프로세스가 로드한 패키지들의 **CSV** — 원본 수집 신호라 정규화하지 않는다(쪼개도 이득 없음).

### tb_processes — 실행 프로세스(포트 없어도)
`id [PRI]`, `scan_id [FK]`, `container_id`, `pid`, `comm`, `username`, `exe_pkg [MUL]`, `loaded_pkgs`
- "실행중/사용중"까지 잡아 상태를 정밀 구분(설치만 vs 로드 vs 실행 vs 노출). `loaded_pkgs` 는 exposures 와 동일하게 CSV 신호.

### tb_containers — 컨테이너 인벤토리
`id [PRI]`, `scan_id [FK]`, `cid`, `name`, `image`, `os_id`, `os_version`, `manager`, `pkg_count`
- 컨테이너별 메타. 컨테이너 내부 패키지·프로세스·노출은 각 테이블의 `container_id` 로 연결(호스트 신호가 컨테이너로 새지 않게 격리).

## 2. CVE 도메인 — 검증된 피드에서 상속(스캔과 독립)

> 이 계열은 FK 를 걸지 않는다 — 피드마다 수집 순서가 독립이라 `cve_id` VARCHAR 자연키로 애플리케이션 조인한다(의도).

### tb_cves — CVE 마스터(NVD)
`cve_id [PRI]`, `summary`, `cvss`, `cvss_vector`, `cwe`, `epss`, `epss_percentile`, `published`
- `cve_id` 자연키 PK. 운영은 수십만 행(NVD 전체). CVSS·EPSS 의 **단일 진실 원천** — 화면은 여기서 라이브 조인해야 최신값을 본다.

### tb_kev_catalog — CISA KEV(악용 확인 목록)
`cve_id [PRI]`, `date_added`, `due_date`, `ransomware`, `note`
- KEV 등재 = 우선순위 상향. `due_date` 있으면 패치 기한 초과 판정.

### tb_cve_affected_packages — CVE ↔ 영향 패키지
`id [PRI]`, `cve_id [MUL]`, `ecosystem`, `package_name [MUL]`, `fixed_version`
- **자연키 UNIQUE(cve_id, package_name, ecosystem)** — `ecosystem` 을 키에 넣어야 같은 패키지의 배포판별 조치버전이 안 덮어써진다(예: nginx 가 Rocky·Debian 각기 다른 fixed_version). upsert 는 ON DUPLICATE KEY.

### tb_package_summary — 영향 패키지 사전집계(packages.php 전용)
`package_name [PRI]`, `ecosystem [PRI]`, `cve_cnt`, `max_epss`, `fix_cnt`, `max_fixed`, `updated_at`
- `tb_cve_affected_packages`(92만 행)를 매 로드마다 GROUP BY 하던 packages.php 를 위한 요약(8초→0.3초). `cve_cnt`=COUNT(DISTINCT cve_id), `max_epss`=MAX(tb_cves.epss), `fix_cnt`=조치버전 있는 행 수.
- `max_fixed`: 조치버전의 자연순 최댓값. SQL `MAX()` 로는 못 구해(사전순이라 `...9` > `...11`) OSV 커넥터 실행 뒤 `vg_rebuild_package_summary()`(matcher.php)가 PHP 에서 계산해 채운다.
- OSV 커넥터가 돌 때만 `vg_rebuild_package_summary()` 가 트랜잭션으로 통째 재생성(읽는 쪽은 MVCC 로 옛 값을 보다 커밋 때 전환).

### tb_advisories — 국내 보안공지(KISA)
`id [PRI]`, `source`, `title`, `url [UNI]`, `published [MUL]`, `cve_ids`, `content`, `content_fetched_at`, `fetched_at`
- `url` 유니크. `content` 는 원문 본문. `cve_ids`(CSV)는 **호환용으로 유지** — 읽기는 아래 junction 이 정본(§정규화 참고).

### tb_advisory_cves — 공지 ↔ CVE 정션(1NF 정규화)
`id [PRI]`, `advisory_id [FK CASCADE]`, `cve_id [MUL]`
- `tb_advisories.cve_ids` CSV 를 정규화한 정션. **UNIQUE(advisory_id, cve_id)** + `cve_id` 인덱스(CVE→공지 역조회). 화면 읽기는 여기서. 쓰기는 `vg_sync_advisory_cves` 가 멱등 동기화.

## 3. 매칭 결과 — 우리 기여(런타임 상태·억제)

### tb_findings — 매처 판정(취약점) ★핵심
`id [PRI]`, `scan_id [FK]`, `container_id`, `cve_id [MUL]`, `package_name`, `installed_version`,
`loaded`, `exposed`, `exposure_scope`, `runtime_status`, `in_kev`, `needs_restart`, `no_fix`,
`cvss`, `severity [MUL]`, `rationale`, `matched_at`
- 스캔×CVE×패키지 판정. `runtime_status` = EXTERNAL/LISTENING/RUNNING/LOADED/INSTALLED 5단계.
- **의도적 캐시(비정규화)**: `cvss`·`in_kev`·`severity` 는 tb_cves/kev 값을 복제 보관한다. rematch 가 DELETE+INSERT 로 재계산하는 **머티리얼라이즈드 뷰**라 성능상 정당하다(3NF 위반 아님, 재계산 경로가 정합성 보장).
- `no_fix`: 벤더가 "아직 안 고쳤다"(조치 불가)고 확인한 건 표시(`tb_vendor_unfixed` 대조). 등급은 그대로 두되(런타임 노출 기준) "지금 고칠 수 있는 것"과 화면에서 분리 — 조치 불가가 덜 위험하다는 뜻이 아니라 지금 할 수 있는 일이 없다는 뜻.

### tb_suppressed_findings — 억제된 건(설명가능한 오탐 억제)
`id [PRI]`, `scan_id [FK]`, `cve_id`, `package_name`, `installed_version`, `in_kev`, `cvss`,
`base_severity`, `suppress_reason`, `matched_at`
- 백포트 등으로 "이미 패치됨"이 증명돼 findings 에서 뺀 건. 숨기지 않고 근거(`suppress_reason`)와 함께 호스트 상세에 표시.

### 억제 근거 4종(스캔에 매달림, 매처가 참조)
| 테이블 | 컬럼 | 역할 |
|---|---|---|
| `tb_pkg_changelog_cves` | `scan_id`, `package_name`, `cve_id`, `evidence` | ② changelog 에 그 CVE 수정 기록 |
| `tb_applied_errata` | `scan_id`, `package_name`, `cve_id`, `evidence` | ③ 벤더가 "이 빌드에서 고쳤다" 확인 |
| `tb_debsecan` | `scan_id`, `cve_id`, `package_name` | ④ 데비안 트래커에 **없으면** 고쳐진 것(역방향) |
| `tb_stale_libs` | `scan_id`, `pid`, `comm`, `package_name`, `lib_path` | 억제 **취소** — 패치됐지만 옛 .so 물고 있음 → 재시작 필요 |

### 벤더별 판정 소스(배포판·커널의 중앙 OVAL/에라타 카탈로그)
데비안 계열은 `tb_debsecan`/`tb_applied_errata`(위 표)가 담당하고, 나머지 배포판·커널은 아래 테이블이 같은 역할(백포트로 인한 오탐 방지·조치 불가 판정)을 한다. 모두 스캔에 매달리지 않고 벤더 피드에서 독립적으로 채워지며, 매처가 참조한다.

#### tb_ubuntu_oval — 우분투 벤더 판정(Canonical OVAL)
`id [PRI]`, `release_codename [MUL]`, `pkg_name`, `cve_id`, `fixed_evr`, `severity`, 감사4컬럼
- **UNIQUE(release_codename, pkg_name, cve_id)**. `fixed_evr` = NULL 이면 "아직 수정본 없음"(조치 불가) — Canonical OVAL 테스트에 state 가 없는 경우. 데비안/RHEL 계열과 달리 우분투는 이 하나로 조치버전·조치불가를 모두 표현.

#### tb_vendor_errata — RHEL 계열 벤더 권고(OVAL)
`id [PRI]`, `vendor`, `release_major`, `pkg_name [MUL]`, `cve_id`, `fixed_evr`, `advisory`, `severity`, 감사4컬럼
- `vendor` = redhat/almalinux(Rocky 는 OSV 가 이미 조치버전을 주므로 제외 — 중복 수집 회피). **UNIQUE(vendor, release_major, pkg_name, cve_id, fixed_evr)** — 같은 (패키지,CVE)가 마이너 릴리스마다 다른 EVR 로 고쳐지므로(el9_2·el9_4…) EVR 까지 키에 넣어 전부 보관한다.

#### tb_vendor_unfixed — Red Hat 미수정 CVE(조치 불가)
`id [PRI]`, `vendor`, `release_major`, `component [MUL]`, `cve_id`, `fix_state`, `severity`, `cvss`, `checked_at`, 감사4컬럼
- `tb_vendor_errata`(OVAL)엔 수정본이 나온 것만 있어, Red Hat 이 "영향받음/고치지 않겠다/조사중/지원종료" 로 표시한 CVE 는 별도로 담는다(실측 UBI8: Trivy 523건 중 514건이 이것). **UNIQUE(vendor, release_major, component, cve_id)**. `component` 는 소스 패키지 단위(bzip2) — 설치된 바이너리에 펼쳐 `tb_findings.no_fix` 로 표시.

#### tb_kernel_cves / tb_kernel_cve_fixes — 커널 CVE(kernel.org CNA 판정)
- `tb_kernel_cves`: `cve_id [PRI]`, `introduced_version`, `mainline_fixed`, 감사(created/updated만)
- `tb_kernel_cve_fixes`: `cve_id+stream [PRI]`, `fixed_version`
- 커널은 배포판 버전 체계 밖(예: `linux-image-6.18.34+rpt-rpi-2712`)이라 배포판 트래커/OVAL 로 판정이 안 된다. kernel.org CNA 가 "어느 stable 시리즈의 어느 버전에서 고쳤는가"를 발행 — 구동 커널의 업스트림 버전과 대조해 배포판 무관하게 판정. 억제 방향으로만 쓴다(배포판이 업스트림보다 먼저 백포트한 경우는 억제하지 않고 트래커/OVAL 에 맡김 — 보수적).

## 4. 설정 점검·변화 추적

### tb_cce_findings — 보안설정 점검(CCE)
`id [PRI]`, `scan_id [FK]`, `code`, `ssg_rule_id`, `title`, `result [MUL]`, `severity`, `evidence`, `rationale`, `checked_at`
- CVE 가 아니라 잘못된 **설정**(SSH root 로그인·패스워드 인증·UID 0·MAC·방화벽) 판정. `result` = PASS/FAIL/NA. 신규 수집 없이 기존 수집물 재활용.
- `ssg_rule_id`: 이 점검이 묶인 SCAP Security Guide 룰 ID(`tb_compliance_rules.rule_id`). 비어 있으면 아직 SSG 에 매핑되지 않은(=우리만의) 점검.

### tb_compliance_rules — 보안설정 룰 카탈로그(SCAP Security Guide)
`id [PRI]`, `rule_id [UNI]`, `title`, `severity`, `rationale`, `refs_json`, `ssg_version`, 감사4컬럼
- 점검 룰을 코드에 직접 써 넣던 것(MITRE CCE 는 갱신 끊김, KISA 가이드는 API 없음)을 대신해, 오픈소스 룰셋 SSG(ComplianceAsCode)를 카탈로그로 받는다. `refs_json`: `{"cis@rhel9":"5.2.11","nist":"AC-17(a)","stig":"..."}` 형태로 CIS/NIST 800-53/STIG/PCI-DSS 참조를 담는다.
- 판정 로직(OVAL)까지 중앙화하진 못한다 — OVAL 은 살아있는 파일시스템을 프로브하는데 중앙은 에이전트가 보낸 사실만 가진다. 그래서 판정 가능한 룰만 `tb_cce_findings.ssg_rule_id` 로 묶고, 나머지는 "수집 항목 없음(판정 불가)"로 드러낸다.

### tb_pkg_changes — 패키지 변화 이력(시계열)
`id [PRI]`, `host_id [FK]`, `scan_id [FK]`, `manager`, `package_name`, `change_type`, `old_version`, `new_version`
- 최근 2개 스캔 대조로 설치/제거/업그레이드/다운그레이드 기록. 차별점 ④(변화 추적).

## 정규화 현황 (요약)

스키마는 **대체로 3NF**다. "다 쪼갰나?"에 대한 정직한 답:

**정규화한 것**
- `tb_cve_affected_packages`: 자연키 UNIQUE(cve_id, package_name, **ecosystem**) — 배포판별 조치버전이 서로 덮어쓰던 2NF 버그 수정.
- `tb_advisory_cves`: `tb_advisories.cve_ids` CSV → 정션(1NF). CVE 역조회·인덱스 검색 가능.
- 인덱스 보강: `tb_findings.cve_id` 등 라이브 조인 경로.

**의도적 비정규화(위반 아님 — 그대로 둔다)**
- `tb_findings` 의 cvss/severity/in_kev: rematch 가 재계산하는 **캐시(머티리얼라이즈드 뷰)**. 성능상 정당, 정합성은 재계산 경로가 보장.
- `tb_scans` 의 os/kernel 등: 수집 **시점 스냅샷**(현재값 복제가 아니라 시점 사실).
- `tb_exposures`/`tb_processes` 의 `loaded_pkgs` CSV: **원본 수집 신호** — 쪼개도 이득 없어 그대로.
- `tb_advisories.cve_ids` CSV: junction 도입 후에도 호환 위해 유지(expand→contract 의 expand 단계). 읽기 정본은 junction.

**FK 정책**
- 스캔 소유 계열(scan_id·host_id·connector_id·advisory_id)엔 FK. CVE 도메인(cve_id 자연키)엔 FK 를 안 건다 — 피드별 수집 순서 독립성을 위해 애플리케이션 조인(의도적 설계).
