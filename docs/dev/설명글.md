# 런타임 맥락으로 오탐을 줄이는 취약점 진단 에이전트

> 문서 기준: 2026-08-21 · 현재 운영 UI와 에이전트 3.22 기준.

> 쉬운 설명용 문서. 정확한 구조는 [`architecture.md`](architecture.md), 전략·현황은
> [`CONTEXT.md`](../../CONTEXT.md) 를 본다.

## 한마디로 무엇인가

서버에 깔린 소프트웨어 중 **보안 구멍(취약점)이 있는 것을 찾아내고, 그중 진짜 위험한 게
무엇인지 판단해 우선순위와 조치안을 알려주는** 시스템입니다.

각 서버에 가벼운 수집 에이전트(셸 스크립트)를 두고, 그 결과를 중앙 서버(PHP + MySQL)가 CVE
데이터베이스와 대조합니다. 에이전트가 깔리지 않은 장비는 중앙이 관리 대역을 훑어 찾아냅니다.
전체 흐름은 그림 한 장으로 볼 수 있습니다 — [수집 → 연결 → 검증 → 조치 흐름도](../readme-flow.svg).

---

## 왜 필요한가

요즘 서버는 수백 개의 오픈소스 패키지를 끌어다 씁니다. 기존 스캐너를 돌리면 취약점이 수백 개씩
쏟아지는데 그중 상당수가 **오탐**이고, 담당자가 "이건 진짜인가, 이미 고쳐진 건가"를 손으로
확인하다 지치면 결국 아무도 그 목록을 안 보게 됩니다.

그래서 필요한 건 "더 많은 경고"가 아니라 **"믿을 수 있는 소수의 판단"** 입니다.

## 어떻게 오탐을 줄이나 — 두 가지 축

### ① 백포트 억제 — "버전은 낮아 보여도 이미 패치됐다"

리눅스 배포판은 **백포트(backport)** 를 씁니다 — 버전 번호는 그대로 두고 보안 패치 코드만 콕 집어
이식하는 방식이죠. 겉보기 버전은 낮아도 내부는 이미 고쳐진 상태라 **버전 번호만 보는** 스캐너는
이걸 "취약"이라고 잘못 잡습니다. 그래서 **서로 다른 출처 네 겹**이 같은 이야기를 하는지 봅니다.

| 겹 | 무엇에 물어보나 | 적용 범위 |
|---|---|---|
| 배포판 버전 대조 | 배포판이 실제로 배포한 버전 범위(릴리스 번호까지) | 모든 패키지 — 가장 넓은 그물 |
| 변경기록(changelog) 대조 | **호스트 자신** — "이 CVE를 고쳤다"는 줄이 있는가 | 변경기록을 자세히 남기는 핵심 패키지 십여 종 |
| 벤더 패치 확인(errata) | 배포판을 만든 쪽의 공식 수정 확인 목록 | 시스템 전체(변경기록 없는 패키지까지) |
| 미수정 CVE 목록 대조 | 데비안의 "아직 안 고쳐진" 목록 — **없으면** 고쳐진 것 | 데비안 계열, 앞 세 겹과 반대 방향의 확인 |

이 네 겹은 데비안 계열 중심이라, 레드햇 계열·우분투·커널처럼 기준이 다른 대상은 **각 벤더가 직접
내놓는 자료로 따로 판정합니다.** 억제한 건은 숨기지 않고 **네 겹 중 무엇이 근거였는지를 화면에
남깁니다** — 사람이 검증할 수 있어야 하니까요(판정 계층의 구조는 [`architecture.md`](architecture.md)).

#### 고쳤다고 다 끝난 건 아닙니다 — 억제를 취소하는 두 신호

아래 두 경우는 **패치를 확인했더라도 억제하지 않고 그대로 위험으로 남깁니다.** 여기서 봐주면
"패치됐으니 안전하다"고 착각해 진짜 위험을 놓칩니다.

- **재시작이 필요한 경우** — 파일은 새 버전으로 바뀌었지만 이미 돌고 있던 프로세스가 **옛
  라이브러리를 메모리에 그대로 물고 있어** 지금도 옛 코드를 실행 중입니다. 조치는 그 프로세스 재시작.
- **재부팅이 필요한 경우** — 커널은 패치해도 재부팅 전까지는 옛 커널이 돕니다. 조치는 재부팅.

### ② 런타임 노출 맥락 — "설치됐다고 다 위험한 건 아니다"

취약한 패키지가 깔려 있어도 아무도 실행하지 않으면 공격 경로가 없고, 반대로 외부에 포트를 열고 도는
프로세스가 그 라이브러리를 쓰고 있다면 즉시 위험합니다. 그래서 에이전트는 패키지 목록만이 아니라
**실행 중인 프로세스, 그 프로세스가 로드한 라이브러리, 열려 있는 포트**까지 함께 수집하고,
매처는 이걸 이어 붙여 7단계로 나눕니다.

| 상태 | 뜻 | 등급 |
|---|---|---|
| 외부노출 | 외부(0.0.0.0)로 포트를 열고 그 패키지를 씀 | 높음 (+ KEV → 최상) |
| 로컬 세그먼트 노출 | 같은 네트워크 안에서만 보임 — 공유기·라우터를 넘어가지 않음 | 중간 |
| 방화벽 차단 | 포트는 열려 있지만 방화벽이 막아 밖에서 닿지 못함 | 중간 |
| 로컬리스닝 | 포트를 열지만 127.0.0.1 만 | 중간 |
| 실행중 | 실행 중이나 포트는 안 엶 | 중간 |
| 사용중 | 다른 프로세스가 그 라이브러리를 로드 | 중간 |
| 설치만 | 아무도 안 씀 | 낮음 |

여기에 **실제 악용 정보**를 얹습니다. **CISA KEV**(이미 공격에 쓰이고 있다고 확인된 목록)에 있으면
등급을 한 단계 올리고, **EPSS**(앞으로 30일 내 악용될 확률)로 같은 등급 안에서 순서를 매깁니다.
CVSS 점수만 보고 줄 세우지 않습니다. **핵심 규칙: 외부 노출 + KEV = CRITICAL.**

## 어떻게 동작하나

1. **수집** — 각 서버의 에이전트가 패키지·실행 프로세스·열린 포트·changelog·보안설정을 읽습니다.
   읽기 전용이고 최저 우선순위(nice 19)로 돌아 서버에 부담을 주지 않습니다.
2. **전송** — 결과를 JSON으로 중앙에 POST합니다. 설치 한 번이면 상시 데몬이 10초마다 중앙을
   poll 하다 주기가 되면 알아서 재실행합니다 — 주기를 바꿔도 재설치가 필요 없습니다.
3. **매칭** — 중앙이 외부 보안 피드와 대조합니다(고정 11종 + 조직이 직접 등록하는 범용 API).
   각 피드는 서로 다른 질문에 답합니다 — [`피드소스-역할.md`](피드소스-역할.md).
4. **판단** — 백포트를 억제하고, 런타임 상태 + KEV/EPSS로 우선순위를 매깁니다.
5. **표시** — 웹에서 우선순위·판단 근거·조치안("어느 버전 이상으로 올리면 된다")을 보여줍니다.

여기에 더해 세 갈래를 더 봅니다.

**① 서버에서 직접 보는 것**

- **보안설정 점검(CCE)** — "취약한 버전"이 아니라 **"잘못된 설정"** 도 봅니다. SSH root 로그인 허용,
  root 외 UID 0 계정, SELinux/AppArmor 비활성, 방화벽 없음 같은 항목을 수집한 데이터로 판정합니다.
- **계정 인벤토리** — 계정 목록과 각 계정의 마지막 로그인·잠금·관리자 권한을 모아 오래 안 쓴 계정,
  여럿이 함께 쓰는 것으로 보이는 계정을 짚어 줍니다. **비밀번호는 해시조차 수집·저장하지 않습니다.**
- **자산 등급(N2SF C/S/O)** — 등급 확정은 법이 정한 기관의 판단이라 시스템이 대신하지 않고, 수집한
  사실로 **초안만** 제안합니다. 확정값과 제안값은 아예 다른 칸에 담깁니다 — [자산 등급](자산등급.md).
- **패키지 무결성 검증** — "설치된 파일이 그 뒤에 바뀌었나"를 `rpm -Va`/`dpkg --verify` 로 봅니다.
  무거워서 **선택 기능**이고, 켜지 않은 자산은 "정상"이 아니라 **미수행**입니다(잘린 검사도 표시).
- **자산 탐색과 세그먼트 맵** — 안 깐 장비는 위험이 0으로 보이므로, 관리 대역을 중앙에서 훑어(TCP 연결
  2단계) 응답하는 IP를 찾고 역DNS·서비스 힌트·배너로 정체를 채웁니다. 라우팅 정보로 대역 구분도 그립니다.

**② 소프트웨어 구성에서 보는 것**

- **오픈소스 구성요소 분석(SCA)과 부품표(SBOM)** — 운영체제 패키지만이 아니라 애플리케이션이 쓰는 언어
  패키지 8종(pip·npm·gem·composer·maven·nuget·cargo·go)도 CVE와 맞춰 봅니다. 라이선스는 허용적·카피레프트·
  **미상**으로 나누고(근거가 없으면 미상), 부품표는 CycloneDX 1.5·SPDX 2.3 으로 내려받을 수 있습니다.
- **의존성 그래프와 전이 의존성** — "무엇이 이 패키지를 끌어왔나"를 역추적합니다. 다른 패키지가 딸려
  온 것이면 그것만 갈아끼울 수 없으므로 조치를 **"직접 조치 불가 — X가 끌어옴"** 으로 바꾸고 부모별로
  "이 하나를 올리면 N건 해결"을 먼저 보여줍니다. 다만 **올릴 버전은 제안하지 않습니다**(설치되지 않은
  부모가 무엇을 끌어오는지는 수집한 자료로 알 수 없습니다).
- **제거·대체 검토 권고** — 벤더 미수정 CVE가 한 패키지에 수십 건씩 몰리면 실제 조치는 **그 패키지를
  지우거나 바꾸는 것** 하나뿐이라 (자산 × 패키지)로 묶어 권고합니다(EOL 단정이 아니라 관측입니다).

**③ 운영·증적·외부 연계**

- **조치 상태와 미조치 사유** — 사유·승인자와 상태 4종(미조치·조치중·완료·예외)뿐이고 **결재 워크플로는
  만들지 않습니다** — 담당자·결재선은 사내 시스템의 몫입니다(예외 표시가 자동 억제는 아닙니다).
- **변화 추적** — 지난 스캔과 비교해 무엇이 새로 생기고, 해결되고, 등급이 바뀌었는지 보여줍니다.
- **국내 보안공지(KISA)** — 보호나라 공지를 본문까지 수집합니다. 해외 스캐너가 하지 않는 지점입니다.
- **컴플라이언스 자동판정** — 이미 모아 둔 데이터로 채울 수 있는 항목(패치 관리·자산 식별·보안시스템 운영 등)만 자동으로 매기고, 하루 한 번 기록으로 남깁니다.
- **기반시설 U-코드 커버리지** — 「주요정보통신기반시설」 가이드의 UNIX 서버 항목 **72개를 분모로** 세우고,
  닿는 21개 외 51개는 **빈칸 그대로** 남깁니다 — 지우면 커버리지가 100%로 보입니다(아래와 같은 함정).
- **결과 내보내기** — 다른 시스템(예: AI 보고서 생성기)이 가져갈 JSON/XML API를 제공합니다. AI 문서
  생성은 본체에 넣지 않고 경계 밖으로 분리했습니다.

### "모른다"를 "괜찮다"로 바꾸지 않습니다 — 판정 불가

**확인할 데이터가 없는 것과, 확인해 봤더니 문제가 없는 것은 전혀 다른데** 화면에서는 둘 다 "이상 없음"
으로 보이기 쉽습니다. 그래서 판정을 **준수 / 판정 불가 / 부분준수 / 미준수** 로 나눕니다 — 방금 등록해
기록이 며칠치뿐이면 "기한 안에 조치했는가"는 준수가 아니라 **판정 불가**입니다. 보안 설정·계정 점검도
같습니다 — 권한이 없어 못 읽었으면 통과가 아니라 "판정 불가", 사람이 확인해야 하는 항목은 위반이
아니라 "확인 필요"입니다. 기한처럼 조직마다 다른 값은 설정 화면에서 바꿉니다.

## 무엇이 다른가

| 구분 | 기존 스캐너 | 이 시스템 |
|---|---|---|
| 오탐 처리 | 버전 번호로만 판정 | **근거 4겹으로 백포트 억제**(버전·변경기록·벤더 확인·미수정 목록) + 벤더별 별도 판정, 근거 표시 |
| 우선순위 | CVSS 점수 나열 | **런타임 노출 맥락** + KEV(실제 악용) + EPSS(악용 확률) |
| 설명 | 결과만 제시 | 왜 위험한지·왜 안전한지 **근거를 남김** |
| 점검 범위 | 취약한 버전 | 취약한 버전 + **잘못된 설정(CCE)** + **계정 인벤토리** |
| 자료가 없을 때 | 조용히 "이상 없음" | **판정 불가**로 구분해 표시 |
| 점검 대상 | 에이전트를 깐 서버만 | 관리 대역을 훑어 **안 깐 장비**까지 셈 |
| 국내 정보 | 없음 | **KISA 국내 보안공지** 연동 + 기반시설 U-코드 커버리지 |

**목록에 없는 서버가 가장 위험합니다.** 안 깐 서버는 목록에 아예 없으니 위험도 0으로 보이고 아무도
떠올리지 않습니다 — 사라진 줄 알았던 테스트 장비, 부서가 따로 올린 서버, 계약이 끝난 협력사 장비가
그렇게 남습니다. vuln-agent 는 반대로 **모르는 장비부터 셉니다.**

**설계 원칙 하나: 스캐너를 새로 만들지 않습니다.** CVE 매칭 자체는 이미 검증된 공개
데이터(OSV·NVD·KEV·EPSS)에서 상속받고, 우리 기여는 그 위 레이어 — **런타임 맥락으로 판단하고,
오탐을 근거와 함께 억제하는 것** — 에 둡니다.
