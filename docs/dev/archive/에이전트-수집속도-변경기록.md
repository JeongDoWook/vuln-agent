# 에이전트 수집 속도 — 2026-08-06 · 08-19 변경 기록

> `docs/dev/에이전트-리소스-프로파일.md` 에서 옮겨 온 지난 작업 기록이다. **두 건 모두 그 문서의
> 실측표(2026-08-04 · 에이전트 3.8)에는 반영돼 있지 않다** — 재측정 없이 숫자를 손대지 않았다.
> 효과를 숫자로 보려면 해당 서버에서 `tests/agent-bench.sh` 를 전/후로 돌려 비교한다.

## 2026-08-19 프로세스 스캔 컷오프 설정화

`collect_processes` 의 `/proc` 순회 상한이 코드에 박힌 **90초**였다. 프로세스가 많은 호스트는
그 안에 다 못 훑어 잘렸고(462개 프로세스 호스트 실측 744초), 화면에는 "권한·환경 문제"로
잘못 안내됐다. 상한을 `PROC_SCAN_TIMEOUT` 환경변수로 빼고 기본값을 **180초로 올렸다**.

- 값은 숫자·범위(30~3600초)를 검증한다 — 검증 없이 두면 잘못된 값이 컷오프를 조용히
  무력화해 탐지 회피에 쓰일 수 있었다.
- **속도 티어와는 아직 연동되지 않는다**(`CPU_QUOTA`·`PACKAGING_TIMEOUT`·`MEM_MAX` 세 값만 티어가 정한다).
- 화면은 `runtime_processes` 의 MISSING 을 `item_count>0`(시간초과로 일부만) /
  `0`(권한·환경 문제로 전혀 못 걸음)으로 갈라 안내한다.
- **리소스 프로파일의 실측표는 90초 시절 값이다.** 재측정 없이 숫자를 손대지 않는다.

## 2026-08-06 속도 개선 — 무엇이 바뀌었나

같은 날 두 건이 들어갔다. 무엇이 바뀌었는지만 남긴다.

- **프로세스/노출 스캔의 중복 작업 제거.** `collect_processes` 와 `collect_stale` 이 같은 pid
  목록을 각자 순회하며 `/proc/PID/maps` 를 최대 3~4회씩 다시 읽고 있었고, `file_to_pkg` 의
  라이브러리→패키지 조회 캐시는 호출부가 파이프 서브셸 안이라 **매번 무효화**됐다(실측: 367개
  프로세스 스캔 동안 부모 셸 캐시 히트 0건 — 전부 awk fork 로 재조회). 호출부를 here-string 으로
  바꿔 캐시가 실제로 누적되게 하고, 삭제된 `.so` 매핑을 같은 순회에서 함께 뽑아 순회를 1회로
  합쳤다. 출력 필드·값은 동일하다.
  - 부수 효과: 프로세스 순회가 컷오프에 걸려 잘리면 `meta.processes_truncated=1` 이
    페이로드에 실린다 — "재시작 필요" 판정이 조용히 미탐되지 않게.
- **메모리 상한(`mem_max_mb`)이 속도 티어에 추가됐다.** 그전엔 CPU·타임아웃만 티어로 조절되고
  메모리는 **항상 300M 고정**이었다 — 실측 `peak_rss` 350.2MB 를 낸 호스트(raspberrypi5-04)가
  cgroup 상한에 걸리는데 낮출/올릴 손잡이가 없었다. 이제 CPU 처럼 티어로 조절한다.
- **`collect_pkg_origins()` 진행 하트비트.** `apt-cache policy` 를 패키지 수천 개에 한 번에
  돌리면 수 분이 걸릴 수 있는데 그동안 진행 신호가 없어 웹 UI 가 "마지막 통신 180초 경과"로
  지연을 오탐했다(실측: 패키지 2,248개 우분투 노드). 백그라운드 실행 + 5초 간격 하트비트로
  바꿨다. **이건 빨라진 게 아니라 "느린 동안 살아 있음을 알리는" 개선이다** — CPU·메모리
  비용은 사실상 그대로다.
