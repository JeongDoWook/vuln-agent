# UI 디자인 시스템

`server/public/assets/app.css`와 `server/src/view/components.php`가 화면 표현의 정본이다. `/styleguide.php`에서 실제 공통 헬퍼 결과를 Light/Dark로 비교한다.

## 텍스트 예산

- 제목 아래 부제는 한 줄, 40자 이하이며 불필요하면 삭제한다.
- 결론 배너는 행동을 말하는 한 문장만 둔다. 근거는 `vg_verdict()` 숫자 슬롯으로 분리한다.
- 표 셀에는 문장을 쓰지 않는다. 배지·숫자·짧은 명사구만 둔다.
- “이 화면이 증명하는 것은” 같은 화면 자체의 메타 설명은 삭제한다.

## 문구

컨트롤(고르고 누르는 것)은 **단어**로 쓰고, 문장은 **안내에만** 쓴다. 컨트롤 자리에 말을 거는
문장(`고르세요`)이 들어가면 값처럼 읽히지 않아 훑을 때 걸린다.

### 컨트롤은 단어다

- 셀렉트의 옵션, 버튼, 탭, 필터 라벨, 표 머리글은 명사(구) 또는 동사 한 단어로 쓴다.
- 무엇을 고르는지 분명해야 하면 `호스트 선택`처럼 명사구로 늘린다. `~하세요`·`~해 주세요` 같은
  말을 거는 형태는 컨트롤에 쓰지 않는다.
- 버튼은 그 버튼이 하는 일을 동사로 쓰고(`발급`·`추가`·`저장`·`실행`), 누른 뒤의 확인 문구도
  같은 동사를 쓴다(`발급` → `토큰이 발급되었습니다`). 같은 동작에 화면마다 다른 동사를 쓰지 않는다.

### 셀렉트 빈 값 옵션의 정본

`value=""` 옵션은 **다섯 갈래로 갈려 있었다**(`고르세요`·`미지정`·`미검토`·`변경 안 함`·`미지정(확정 해제)`).
빈 값이 **무엇을 뜻하는지**로 다섯 가지가 아니라 아래 다섯 **역할**로 가른다 — 역할이 같으면 표기도 같다.

| 역할 | 정본 | 쓰는 곳 |
| --- | --- | --- |
| 이 축으로 좁히지 않음(필터) | `전체 <대상>` | `vg_toolbar()`의 필터 셀렉트 |
| 기본 정렬(정렬 셀렉트) | `<정렬명>(기본)` | 목록의 정렬 셀렉트 |
| 아직 안 골랐음, 골라야 함(required) | `선택` | 등급 일괄 확정의 보안등급 |
| 비워 두면 값 없음으로 저장됨 | `미지정` | 자산 상세의 중요도·제9조 해당 호·공개 상태 |
| 일괄 편집에서 이 항목은 건드리지 않음 | `변경 안 함` | 등급 일괄 확정의 중요도 |

- `전체`는 **`전체 <대상>` 어순으로 고정한다** — `심각도 전체`처럼 뒤에 붙이지 않는다.
- `미검토`는 `미지정`으로 모은다. 둘 다 “저장된 값이 없다”는 같은 상태이고, 상세 화면에서는
  이미 둘 다 `–` 하나로 표시하고 있었다.
- `변경 안 함`은 남긴다. “그대로 둔다”는 **하나의 선택지**이지 값이 없는 상태가 아니다.
- 빈 값을 고르면 기존 확정이 풀리는 등 부작용이 있으면 괄호로만 덧붙인다: `미지정(확정 해제)`.

### 입력 placeholder 는 지시가 아니라 예시다

- `토큰 이름(용도)을 입력하세요`가 아니라 `예: AI 보고서 생성기`. 라벨이 이미 무엇을 넣는 자리인지
  말하고 있으므로 되풀이하지 않는다.
- 예시 접두는 `예:` 로 통일한다(`예)` 를 쓰지 않는다).
- 비워 뒀을 때의 동작은 예시가 아니라 규칙이므로 그대로 서술한다: `비우면 호스트명으로 자동 지정`.
- 제약(길이·형식)은 placeholder 가 아니라 라벨 옆 `.why` 에 둔다 — placeholder 는 입력하는 순간
  사라져서 제약을 거기 두면 볼 수 없다.

### 문장이 허용되는 곳

오류·경고·확인 메시지, 빈 상태(`vg_empty()`)의 힌트 한 줄, 결론 배너(`vg_verdict()`) 한 문장.
여기서도 **무엇이 잘못됐고 어떻게 고치는지**만 쓴다 — 사과·변명·군더더기를 넣지 않는다.
사용자가 실제로 할 일을 알려주는 안내는 문장이 맞다:
`패치된 라이브러리를 적용하려면 관련 프로세스를 재시작하세요`.

### 금지

- 화면 자체를 설명하는 메타 문장(`이 화면이 증명하는 것은 …`).
- 같은 말을 라벨과 힌트에서 두 번 하기.
- 같은 대상을 화면마다 다른 말로 부르기(`비번` / `비밀번호`, `8자+` / `8자 이상`).
- 영문 기술 용어(CVE·KEV·EPSS·SBOM·CVSS·SSH·fqdn)를 억지로 한글로 옮기기.

## 토큰

- 표면은 `--bg`, `--surface`, `--surface-2` 세 단계다. 내려간 입력·코드 면은 표면 파생 토큰 `--sunken`만 쓴다.
- 심각도는 `crit`, `high`, `med`, `low`, 상태는 `ok`, `muted`를 기본 어휘로 쓴다. Light/Dark 모두 같은 단계가 비슷한 시각 강도로 읽혀야 한다.
- 간격은 `--sp-1`~`--sp-6`, 라운드는 `--r-xs`~`--r-lg`, 그림자는 `--shadow`와 `--shadow-lg`만 쓴다.
- 일반 텍스트는 `--fs-xs`, `--fs-sm`, `--fs-md`, `--fs-lg`, `--fs-xl` 다섯 단계만 쓴다.
- **디스플레이 숫자는 `--fs-num-sm`(1.3rem) / `--fs-num`(1.6rem) / `--fs-num-lg`(2rem) 세 단계만 쓴다.**
  본문 스케일과 나눠 둔 이유는 이 값들이 글이 아니라 지표라, 본문 밀도를 조일 때 같이 줄면 안 되기 때문이다.
  - `--fs-num-sm` — 보조 숫자. 목록 화면 위의 `kpi--sm`, 요약 블록의 `strong`.
  - `--fs-num` — 기본 숫자. 대시보드 `kpi`, 도넛 가운데, `stat-grid`의 점수.
  - `--fs-num-lg` — 결론 숫자. `verdict` 배너, 상세 사이드바의 `score`.
  - 새 숫자를 그릴 때 `rem`을 직접 쓰지 않는다. 세 단으로 안 되면 단을 늘리는 게 아니라 자리를 다시 본다.
    (예전엔 1.25·1.3·1.35·1.5·1.6·1.65·1.7·1.75·1.8·2·2.1rem 열한 개가 같은 역할을 하며 흩어져 있었다.)
  - 네 단이 필요한 유일한 자리는 퍼널(`funnel__step--s1~s4`)이다. 크기 자체가 포함관계를 그리는 그림이라
    단이 넷 필요한데, 새 값을 만들지 않고 `--fs-lg → --fs-num-sm → --fs-num → --fs-num-lg`로 잇는다.
- 예외는 데이터 시각화 SVG의 좌표계 글자와 아이콘의 광학 크기뿐이다. 설명문·라벨에는 예외를 만들지 않는다.

## 버튼 규격

색 계열(`primary`·`ghost`·`secondary`·`danger`·`warn`)은 **서열**을 말하고, 크기 클래스는 **자리**를 말한다.
자리가 같으면 크기도 같아야 한다 — 한 툴바·한 표 행 안에서 크기가 섞이면 그것만으로 눈에 띈다.

| 자리 | 규격 |
|---|---|
| 페이지 머리글의 주 동작(모달 열기, 발급, 추가, 저장) | `btn btn--sm btn--primary` |
| 툴바·form-bar의 보조 동작(초기화, 내보내기, 일괄 작업) | `btn btn--sm btn--ghost` |
| 표 행 안의 인라인 동작(편집·이력·삭제) | `btn btn--xs btn--ghost` |
| 모달 푸터 | `vg_modal_foot()`가 소유한다 — 페이지가 크기 클래스를 직접 쓰지 않는다 |
| 로그인·프로필처럼 폼 하나가 화면인 제출 버튼 | `btn btn--primary btn--block`(크기 없음 = 기본 단) |
| 파괴적 동작(삭제·폐기) | 위 크기를 그대로 두고 `btn--danger`만 바꾼다 |

- 페이지 머리글 버튼은 `vg_page_title(..., ['actions' => …])`로 넣고, 모달을 여는 것이면
  `vg_modal_btn()`을 쓴다(기본값이 이미 `btn btn--sm btn--primary`다).
- 모달 푸터가 크기 클래스를 안 쓰는 것은 의도다 — 기본 `.btn` 한 단으로 모든 모달이 같은 크기·정렬을
  갖는다. `extra`로 넘기는 보조 버튼도 같은 이유로 크기 클래스를 붙이지 않는다.
- `btn--secondary`는 `ghost`와 합치지 않는다. `ghost`는 무채색 외곽선이고 `secondary`는 강조색 외곽선이라
  "주작업은 아니지만 눌러 보라"는 중간 서열을 말한다(연결 미리보기, 표 행의 편집). `/styleguide.php`에서
  두 색이 실제로 갈리는지 확인할 수 있다.

## 공통 컴포넌트

- `vg_kpi_strip()`은 칸 수와 무관하게 같은 격자·톤·0값 규칙을 쓴다. 링크는 앱 내부 경로만 허용한다.
- `vg_verdict()`는 결론 한 문장과 숫자 슬롯을 분리한다. 보조 note는 기준 시각처럼 짧은 출처 표기에만 쓴다.
- `vg_table()`은 행 높이·정렬·말줄임을 소유한다. 긴 원문은 상세 화면이나 툴팁으로 보낸다.
- `vg_signal_slots()`은 노출→악용→등급→조치 순서를 고정한다. CCE처럼 축이 없으면 `state=na`, 아직 값이 없으면 `state=unknown`으로 조용히 남긴다.
- `vg_badge()`와 `vg_empty()`를 재사용하며 새 배지·빈 상태 마크업을 페이지에 직접 만들지 않는다.

### 시각 설명 컴포넌트

글이 아니라 그림으로 설명하는 자리다. CSP가 `default-src 'self'`라 외부 차트 라이브러리·아이콘 폰트를
쓸 수 없다 — 인라인 SVG와 CSS만 쓴다.

- 화면 상단 가로 도식(`vg_explain_flow`)은 **없앴다**(2026-08-17). 도식이 들고 있던 숫자가
  같은 화면의 KPI 줄·제목 건수와 겹쳐 화면마다 같은 값을 두 번 세고 있었다 — 새로 만들지 않는다.
  화면이 무엇을 보여주는지는 제목·부제 한 줄로 말하고, 건별 판단 근거는 `vg_decision_flow()`가 갖는다.
- `vg_icon($name)` — 인라인 SVG 아이콘(`server/src/view/icons.php`). `currentColor`로 그려 테마를
  따라간다. 색을 아이콘에 하드코딩하지 않고, 크기는 CSS(`.vg-ico`)가 정한다. 이모지로 대체하지 않는다
  — 환경에 따라 컬러 이모지 폰트로 렌더돼 색과 정렬이 어긋난다.
- `vg_legend($items, $opts)` — 색이 무슨 뜻인지 점과 단어로 말한다(문장 금지). 색으로 등급·범위를
  말하는 화면에는 그 색의 범례를 같이 둔다. 톤 어휘 밖의 색을 새로 만들지 않는다.
- `vg_meter($tone, $pct, $label)` — 기존 게이지(`format.php`)를 그대로 쓴다. 비율·점수를 새 마크업으로
  다시 만들지 않는다. 폭 `width:N%`만 인라인 style 예외다.

## 목록과 상세의 분담

**목록은 결정에 필요한 열만, 상세가 전부를 갖는다.**
목록 표의 열은 "이 행을 열어볼지 말지"를 정하는 데 필요한 것만 둔다 —
식별자 · 위험도 · 상태 · 시각 정도다. 나머지 값은 지우는 게 아니라 상세 화면으로 옮긴다.
목록 표 열 상한은 **7열**로 둔다(체크박스 열 제외).

## Phase 2 적용 규칙

핵심 화면은 먼저 결론 하나를 정하고 KPI, 표, 신호 슬롯 순으로 근거를 배치한다. 데이터·쿼리는 바꾸지 않고 기존 표시값을 공통 슬롯으로 옮긴다. 네 축 중 없는 값을 추정해 만들지 않는다.
