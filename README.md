# vuln-agent

> 설치된 취약점의 개수보다, **지금 이 서버에서 실제로 위험한 취약점**을 먼저 보여주는 경량 취약점 진단 플랫폼

일반적인 버전 비교는 패키지가 설치돼 있다는 이유만으로 많은 경고를 만듭니다. `vuln-agent`는
설치 패키지에 더해 **실행 중인 프로세스, 로드된 라이브러리, 열린 포트와 방화벽 상태**를 함께 수집합니다.
중앙 서버는 이 실행 맥락과 검증된 보안 피드를 결합해 실제 대응 우선순위를 판단합니다.

억제한 결과도 숨기지 않습니다. “배포판이 보안 패치를 백포트했기 때문”, “프로세스가 아직 옛
라이브러리를 사용 중이기 때문”처럼 **판정 근거와 필요한 조치**를 웹에서 확인할 수 있습니다.

## 무엇이 다른가

| 흔한 취약점 목록 | vuln-agent |
|---|---|
| 설치 버전만 보고 취약 여부 판정 | 실행·로드·리스닝·외부 노출까지 연결해 7단계 상태로 구분 |
| 백포트된 패키지도 오래된 버전처럼 보여 오탐 발생 | OSV 범위와 changelog·errata·벤더 OVAL을 교차 확인 |
| 패치 여부만 안내 | 프로세스 재시작, 커널 재부팅, 이미지 재빌드, 전이 의존성이면 부모 올리기 등 실제 조치 구분 |
| 지원하지 않는 대상도 취약점 0건으로 보일 수 있음 | 피드나 패키지 DB가 없으면 안전이 아닌 **판정 불가**로 표시 |
| 억제된 결과는 보이지 않음 | 억제 사유와 원본 근거를 별도 이력으로 보존 |
| 해외 공통 피드 중심 | CISA KEV·EPSS와 함께 KISA 국내 보안공지 연동 |

### 핵심 기능

각 행이 웹에서 볼 수 있는 화면 하나에 대응합니다. 화면 전체 지도는
[사이트맵 다이어그램](docs/specs/diagrams/사이트맵.svg)에 있습니다.

|---|---|---|
| 런타임 노출 상관 | 취약 라이브러리 → 사용 프로세스 → 리스닝 포트 → 외부 도달까지 이어 7단계 상태로 판정 | [아키텍처 §2](docs/dev/architecture.md) |
| 설명 가능한 오탐 억제 | 배포판 백포트·벤더 수정 근거로 억제하고 억제 사유와 원본 근거를 화면에 남김 | [쉬운 말 설명](docs/dev/설명글.md) · [피드 소스 역할](docs/dev/피드소스-역할.md) |
| 패치 후 잔여 위험 탐지 | 옛 `.so`를 물고 있는 프로세스와 재부팅 전 커널은 억제하지 않고 위험으로 되돌림 | [쉬운 말 설명](docs/dev/설명글.md) |
| 악용 가능성 우선순위 | CVSS에 CISA KEV(실제 악용)와 EPSS(악용 확률)를 얹어 순서를 매김 | [아키텍처 §2](docs/dev/architecture.md) |
| 호스트·컨테이너 인벤토리 | 호스트와 실행 중 컨테이너의 패키지·프로세스·노출을 분리해 수집·표시 | [화면 안내](docs/dev/화면-안내.md) |
| 자산 중요도·N2SF 등급 | 자산마다 중요도(상·중·하)와 C/S/O 등급을 확정값·제안값으로 나눠 관리 | [자산 등급](docs/dev/자산등급.md) |
| 계정 인벤토리 | 실제 계정(UID·셸·잠금·최근 로그인·sudo)을 ISMS-P 2.5.x·N2SF 관점으로 판정 | [화면 안내](docs/dev/화면-안내.md) |
| 보안 설정 점검(CCE) | SSH·계정·권한·시간동기화·로그·암호화 설정을 PASS·FAIL·판정 불가로 구분 | [보안설정 조치 가이드](docs/dev/보안설정-조치가이드.md) |
| 패키지 무결성 검증 | `rpm -Va`/`dpkg --verify` 결과를 미수행·정상·원본과 다름으로 구분(선택 수집) | [화면 안내](docs/dev/화면-안내.md) |
| 컴플라이언스 매핑 | 4개 통제를 ISMS-P·ISO 27001로 자동 판정하고 하루 1건 스냅샷을 남김 | [화면 안내](docs/dev/화면-안내.md) |
| SCA·SBOM 산출 | 8개 언어 생태계 패키지를 CVE와 매칭·라이선스 분류하고 CycloneDX 1.5·SPDX 2.3으로 산출 | [쉬운 말 설명](docs/dev/설명글.md) · [Export API](docs/dev/export-api.md) |
| 의존성 그래프·전이 판정 | 무엇이 이 패키지를 끌어왔는지 역추적하고 "부모 하나를 올리면 N건 해결"로 묶음 | [화면 안내](docs/dev/화면-안내.md) |
| 제거·대체 검토 권고 | 벤더 미수정 CVE가 한 패키지에 몰리면 CVE 수십 건 대신 그 패키지 정리를 권고 | [쉬운 말 설명](docs/dev/설명글.md) |
| 조치 상태·미조치 사유 | 상태 4종과 사유·승인자만 두고 Export API로 넘김(결재 워크플로는 만들지 않음) | [화면 안내](docs/dev/화면-안내.md) · [Export API](docs/dev/export-api.md) |
| 함대 운영 | 웹에서 자산별 즉시·예약 수집, 주기 변경, 진행률 확인과 실행 중단 | [에이전트 가이드](agent/README.md) |
| 변화와 감사 이력 | 수집 실행·패키지·취약점 변화와 사용자 조작, 5요소 접속기록 추적 | [아키텍처 §6](docs/dev/architecture.md) |

이 밖에 외부 보안 피드의 수집 상태·실행 이력, 역할 기반 권한과 호스트별 에이전트 키(유효기간 포함)를
관리하는 화면이 있습니다 — [아키텍처 §6](docs/dev/architecture.md)·[설정 레퍼런스](docs/ui-configuration.md).

## 동작 방식

1. 각 Linux 서버의 Bash 에이전트가 패키지와 런타임 사실을 읽습니다.
2. 에이전트가 아웃바운드 HTTPS로 중앙 서버에 전송합니다. 중앙에서 대상 서버로 접속하지 않습니다.
3. 중앙 매처가 NVD·OSV·KEV·EPSS와 배포판·커널 벤더 피드를 대조합니다.
4. 웹에서 위험도, 실행 맥락, 판정 근거, 조치 버전과 변화 이력을 확인합니다.

더 자세한 구성과 데이터 이동은 [시스템 구성도·ERD·배포 흐름](docs/specs/diagrams/README.md)에서 확인할 수 있습니다.

에이전트는 systemd 환경에서 10초마다 명령을 확인하는 상시 서비스로 동작하며, 무거운 수집은
호스트별 설정 주기에만 실행합니다 — 실행별 CPU·피크 RSS 실측치는
[에이전트 리소스 프로파일](docs/dev/에이전트-리소스-프로파일.md)에 있습니다.

## 자산 등급 (N2SF C/S/O)

자산마다 **업무 중요도**(상·중·하)와 **N2SF 보안등급**을 기록합니다.

| 등급 | 뜻 | 보호수준 |
|---|---|---|
| **C** | 기밀 | 높음 |
| **S** | 민감 | 중간 |
| **O** | 공개 | 낮음 |

**확정은 사람이, 초안은 시스템이.** 등급 확정은 「정보공개법」 제9조 호 매핑에 따른 기관의 법적
처분이라 시스템이 대신할 수 없습니다. 그래서 확정값과 시스템 제안값을 별도 컬럼으로 분리하고,
제안값을 확정 폼에 미리 채우지 않습니다. 제안 규칙(무엇을 관측해 무엇을 제안하는가), 최고등급
승계, 일괄 확정과 제안 이력은 [자산 등급 문서](docs/dev/자산등급.md)에 있습니다.

## 빠르게 실행해 보기

<details>
<summary><strong>Docker Compose로 로컬 개발 환경 실행</strong></summary>

로컬 PHP나 MySQL 설치 없이 실행할 수 있습니다.

```bash
cd deploy
./compose_runner.sh init
./compose_runner.sh doctor
./compose_runner.sh dev up -d
```

웹: <http://localhost:8000>

이 명령은 로컬 확인을 위한 최소 경로입니다. 비밀값 설정, 운영 HTTPS, CA 준비, 백업과 업데이트는
[배포 가이드](deploy/README.md)를 따르세요. 대상 서버에 에이전트를 붙이는 방법은
[에이전트 설치·운영 가이드](agent/README.md)에 분리되어 있습니다.

</details>

## 현재 상태와 검증

수집 → 전송 → 저장 → 피드 매칭 → 런타임 우선순위 → 웹 표시까지 전체 파이프라인이 동작합니다.
현재 에이전트 버전은 **3.13**이며 Ubuntu·Debian과 RHEL 계열의 벤더 판정, 컨테이너 인벤토리,
계정 인벤토리, 설정 점검, 컴플라이언스 판정, 변화 추적과 JSON/XML Export·SBOM API를 포함합니다.

```bash
./tests/smoke.sh http://localhost:8000
./tests/e2e.sh http://localhost:8000
```

Smoke test는 수집·매칭·인증·주요 웹 화면을, Playwright E2E는 테마·반응형 내비게이션·tooltip·모달과
동적 폼을 실제 Chromium에서 검증합니다.
