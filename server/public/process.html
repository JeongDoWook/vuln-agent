vuln-agent 운영자 안내

설치에서 재검증까지, 네 단계

외부 취약점 정보의 피드 동기화와 각 서버의 자산 스캔은 서로 다른 작업입니다. 둘의 최신 상태를 확인한 뒤 실제 노출과 조치 가능성을 기준으로 대응합니다.

  1. 1 / 설치

    키·파일·CA 준비

    호스트 전용 키를 발급하고 설치 스크립트와 루트 CA를 받은 뒤 대상 Linux 서버에 설치합니다.

    에이전트 설치 안내

  2. 2 / 수집

    피드 동기화 + 자산 스캔

    커넥터는 CVE·KEV·EPSS·벤더 근거를 동기화합니다. 에이전트는 패키지·프로세스·노출·설정값을 자산 스캔으로 전송합니다.

    피드 동기화 · 자산 스캔 상태

  3. 3 / 우선순위 확인

    기한·KEV·노출 판단

    대시보드와 탐지 결과에서 기한 초과, KEV, 외부 노출, 재시작 필요 순으로 근거와 영향 대상을 확인합니다.

    탐지 결과

  4. 4 / 조치

    수정 후 다시 자산 스캔

    패치·완화·격리·재시작을 수행하고 다음 자산 스캔에서 판정과 컴플라이언스 추이가 바뀌었는지 재검증합니다.

    컴플라이언스 재검증

완료를 판단하는 기준

  • 설치: 자산 목록에 FQDN과 최신 수집 시각이 나타납니다.
  • 피드 동기화: 커넥터의 마지막 성공 시각이 갱신됩니다.
  • 자산 스캔: tb_scan_run 실행 이력과 필요 시 tb_agent_command 진행 상태가 남습니다.
  • 조치: 새 자산 스캔에서 대상 판정이 해소되거나 남은 이유가 근거와 함께 표시됩니다.

systemd 환경은 정기·즉시·예약 실행과 중단을 지원합니다. cron 폴백은 정기수집만 가능하며 즉시·예약·중단 명령은 지원하지 않는다.

개발자·배포 상세

API, 데이터 모델, 배포 명령과 내부 파이프라인은 운영 첫 흐름에서 분리했습니다.
