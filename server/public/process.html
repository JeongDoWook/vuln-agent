vuln-agent 운영자 안내

설치에서 재검증까지, 네 단계

외부 취약점 정보의 피드 동기화와 각 서버의 자산 수집은 서로 다른 작업입니다. 둘의 최신 상태를 확인한 뒤 실제 노출과 조치 가능성을 기준으로 대응합니다.

  1. 1 / 설치

    키·파일·CA 준비

    호스트 전용 키를 발급하고 설치 스크립트와 루트 CA를 받아 대상 Linux 서버에 설치합니다. 키 원문은 발급 직후 한 번만 표시됩니다.

    에이전트 키 발급 · 설치 안내

  2. 2 / 수집

    피드 동기화 + 자산 수집

    커넥터는 CVE·KEV·EPSS·벤더 근거를 수집합니다. 에이전트는 패키지·프로세스·노출·설정값을 자산 수집으로 전송합니다.

    데이터 수집 · 자산 수집 상태

  3. 3 / 우선순위 확인

    기한·KEV·노출 판단

    대시보드와 탐지 결과에서 기한 초과, KEV, 외부 노출, 재시작 필요 순으로 근거와 영향 대상을 확인합니다. 국내 공지는 보안 공지 화면이 내 자산 기준으로 먼저 보여 줍니다.

    탐지 결과 · 보안 공지

  4. 4 / 조치

    수정 후 다시 자산 수집

    패치·완화·격리·재시작을 수행하고, 다음 자산 수집에서 판정이 바뀌었는지 변화 추적과 컴플라이언스 추이로 재검증합니다.

    변화 추적 · 컴플라이언스

완료를 판단하는 기준

  • 설치 — 자산 목록에 FQDN과 최신 수집 시각이 나타나고, 에이전트 키의 마지막 수신 시각이 채워집니다.
  • 피드 동기화 — 데이터 수집 화면에서 소스별 상태가 성공으로 바뀌고 다음 실행 시각이 갱신됩니다.
  • 자산 수집 — tb_scan_run 실행 이력이 남고, 필요하면 tb_agent_command 진행 상태로 확인합니다.
  • 조치 — 새 자산 수집에서 변화 추적에 '해결'로 잡히거나, 남은 이유가 근거와 함께 표시됩니다.

systemd 환경은 정기·즉시·예약 실행과 중단을 지원합니다. cron 폴백은 정기수집만 가능하며 즉시·예약·중단 명령은 지원하지 않는다.

판정은 중앙에서 한다

에이전트는 수집만 합니다. 취약 여부·심각도·조치 가능 여부는 중앙이 수집한 피드로 판정하므로, 대상 서버에 판정 기준을 배포하거나 맞출 필요가 없습니다. 그래서 2단계의 두 작업(피드 동기화·자산 수집)이 모두 최신이어야 3단계의 판정이 최신입니다.

보안설정 점검(CCE)도 같습니다 — 자산에서 설정값을 수집하고, PASS·FAIL·NA 판정은 중앙의 점검 항목 정의가 내립니다. 수집이 안 된 항목은 PASS 가 아니라 NA(판정 불가)로 남습니다.

개발자·배포 상세

API, 데이터 모델, 배포 명령과 내부 파이프라인은 운영 첫 흐름에서 분리했습니다.
