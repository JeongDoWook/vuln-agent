🛡️ vuln-agent — 전체 프로세스

런타임 노출 맥락으로 오탐을 줄이는 자율 취약점 진단 에이전트 · 2026 오픈소스 개발자대회
Bash 에이전트PHP + MySQL DockerHTTPS(Caddy)OSV · KEV · EPSS · NVD · KISA

각 서버에 경량 에이전트를 두고 설치 패키지·런타임 상태를 수집해 중앙으로 모은다. 단순 스캐너와 다른 점은 “이 취약점이 이 서버에서 실제로 위험한가”를 — 외부 노출·실행·사용 여부와 KEV/EPSS(실제 악용성)로 — 판단해 오탐을 줄이고 우선순위를 매긴다는 것.

2구성요소

에이전트 (Bash, 각 대상 서버)
  • vuln-inventory-agent.sh — 수집 + --send 전송
  • install-agent.sh — 배포·주기 스케줄(systemd/cron)
  • 읽기 전용 · 자원 최저우선(nice19/ionice idle) · 명령별 timeout
중앙 서버 (Docker Compose, dev/prod)
  • caddy — HTTPS 리버스 프록시(운영 전용, Let's Encrypt DNS-01, 현재 자체서명)
  • web — PHP 8.3 / Apache (수신 API + 웹, 외부엔 caddy 통해서만)
  • db — MySQL 8 (수집·매칭 데이터, 내부망만)
  • scheduler — 사이드카(피드 주기 수집·재매칭)
  • 비밀값은 Docker Secrets(txt) · dev/prod 분리

3런타임 상태 — 오탐 감소의 핵심

“설치=취약”으로 전부 올리지 않는다. exposures(포트) + processes(실행/로드) 를 합쳐 각 취약점을 아래 5단계로 구분하고, 실제 노출/사용 여부로 우선순위를 가른다.

상태의미기본 등급
외부노출외부(0.0.0.0) 오픈 포트로 노출 + 사용HIGH (+KEV → CRITICAL)
로컬리스닝리스닝하지만 127.0.0.1 만MEDIUM
실행중실행 중이나 포트 미개방MEDIUM
사용중실행 프로세스가 라이브러리 로드MEDIUM
설치만아무 프로세스도 안 씀LOW
실증: 실 운영 데이터 기준 EXTERNAL(외부노출) 판정 64건 확인. 같은 openssl/glibc 취약점이 — nginx 로 외부노출된 서버에선 CRITICAL, 포트 없는 서버에선 LOW/MEDIUM 으로 갈린다. KEV(이미 악용됨) · EPSS(악용확률)로 실제 악용성까지 반영. 백포트 오탐은 OSV 버전필터가 제거(설치 버전에 실제 영향 주는 것만).

4CVE 피드 커넥터 (5종)

외부 취약점 소스를 UI 에서 설정·미리보기·스케줄(cron/매일/주기)하면 스케줄러가 당겨와 매처가 재계산한다. 매칭 자체는 검증된 소스에서 상속하고, 우리 기여는 그 위 레이어(상태·KEV/EPSS·설명가능성)에 둔다.

커넥터역할채우는 데이터
OSV.dev수집된 전 패키지를 배포판 ecosystem·버전으로 조회 → 취약점 발굴 + 조치버전cve_affected_packages · cves
CISA KEV실제 악용된 취약점 카탈로그(우선순위 가중)kev_catalog
FIRST EPSSCVE 별 악용 확률(0~1)cves.epss
NVD 2.0최근 CVE(CVSS 포함) 증분cves.cvss
KISA 보안공지국내 보안공지(해외 도구 미지원 국내 특화)advisories

5데이터 모델

수집 데이터
  • tb_hosts — 서버(fqdn, OS)
  • tb_scans — 수집 이력(원본 JSON 포함)
  • tb_packages — 패키지(버전·소스패키지·벤더)
  • tb_exposures — 노출 소켓(포트·scope·로드)
  • tb_processes — 실행 프로세스(exe·로드)
취약점 · 판정 · 계정
  • tb_cves — CVE(cvss·epss·요약)
  • tb_kev_catalog — KEV 등재
  • tb_cve_affected_packages — 영향 패키지·조치버전
  • tb_findings — 판정(등급·상태·근거)
  • tb_advisories — 국내 보안공지
  • tb_feed_connectors / _collection_logs — 커넥터·이력
  • tb_users — 웹 계정
  • tb_activity_log — 감사로그(로그인·CRUD·ingest 기록)

전 테이블 tb_ 접두사 통일 + 감사 4컬럼(created_at/updated_at/is_deleted/deleted_at). 삭제는 하드삭제 대신 소프트삭제(is_deleted=1, findings 등 재계산 캐시 테이블은 예외).

6배포 (agent-side push, HTTPS)

중앙이 각 호스트로 들어갈 필요 없이, 각 서버가 로컬 스케줄로 수집해 아웃바운드 HTTPS 하나로 전송. (표준 에이전트 모델)

① 중앙 서버 (내부 서버, Docker + Caddy)
./compose_runner.sh init
./compose_runner.sh prod up -d --build
Caddy 가 Let's Encrypt(DuckDNS DNS-01, 현재는 자체서명)로 TLS 를 종료하고 내부 web:80 으로 프록시 — 인바운드 80/443 개방 없이 기존 8080 포워딩 재사용. ② 각 대상 서버 (에이전트 설치 + 시간마다 자동 수집)
sudo ./agent/install-agent.sh \
  --server https://ost-server.duckdns.org:8080/ingest.php \
  --token <ingest_token> --schedule hourly
systemd-timer(우선)/cron(폴백)으로 자동 등록. 중앙 서버 자신을 스캔하는 로컬 에이전트는 루프백 평문 포트(127.0.0.1:8081)로 직접 전송(외부에서는 접근 불가). ③ 웹 — https://ost-server.duckdns.org:8080 접속 → 서버별 취약점·상태·감사로그 확인
네트워크 요건: 대상 서버 → 중앙 8080 아웃바운드만. 토큰은 /etc/vuln-agent/agent.env(600).

8구현 현황

  • ✓ Docker(dev/prod·secrets) · 수집→전송→저장 파이프라인
  • ✓ 정밀 런타임 수집(실행중/사용중/포트 구분) · 매처 5단계 상태 판정
  • ✓ OSV 자동 매칭(전 패키지·버전필터·조치버전) · KEV/EPSS 우선순위
  • ✓ 웹(로그인·대시보드·호스트상세·취약점·CVE상세·국내공지·커넥터·사용자·감사로그) · 검색/필터·페이지네이션
  • ✓ 피드 커넥터 5종 · cron 스케줄 · 배포 설치기(systemd-timer/cron)
  • ✓ HTTPS 배포 — Caddy 리버스 프록시(Let's Encrypt DNS-01, 현재 자체서명)
  • ✓ DB 전면 개편 — tb_ 접두사 통일 + 감사 4컬럼 + 소프트삭제 + 활동 감사로그(tb_activity_log · activity.php)
