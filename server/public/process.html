각 서버에 경량 에이전트를 두고 설치 패키지·런타임 상태를 수집해 중앙으로 모은다. 단순 스캐너와 다른 점은 “이 취약점이 이 서버에서 실제로 위험한가”를 — 외부 노출·실행·사용 여부와 KEV/EPSS(실제 악용성)로 — 판단해 오탐을 줄이고 우선순위를 매긴다는 것.

3런타임 상태 — 오탐 감소의 핵심

“설치=취약”으로 전부 올리지 않는다. exposures(포트) + processes(실행/로드) 를 합쳐 각 취약점을 아래 7단계로 구분하고, 실제 노출/사용 여부로 우선순위를 가른다.

상태의미기본 등급
외부노출외부(0.0.0.0) 오픈 포트로 노출 + 사용HIGH (+KEV → CRITICAL)
로컬 세그먼트 노출mDNS 등 링크로컬 멀티캐스트 — 같은 세그먼트에만 닿고 라우터를 넘지 않음MEDIUM
방화벽 차단전체 인터페이스에 리스닝하지만 방화벽이 막아 외부 도달 불가MEDIUM
로컬리스닝리스닝하지만 127.0.0.1 만MEDIUM
실행중실행 중이나 포트 미개방MEDIUM
사용중실행 프로세스가 라이브러리 로드MEDIUM
설치만아무 프로세스도 안 씀LOW
실증: 실 운영 데이터 기준 EXTERNAL(외부노출) 판정 64건 확인. 같은 openssl/glibc 취약점이 — nginx 로 외부노출된 서버에선 CRITICAL, 포트 없는 서버에선 LOW/MEDIUM 으로 갈린다. KEV(이미 악용됨) · EPSS(악용확률)로 실제 악용성까지 반영. 백포트 오탐은 버전필터 + changelog 검증 2단으로 억제한다(자세히는 §4).

4백포트 오탐 억제 (2단) — 매처의 첫 관문

배포판은 버전 번호를 그대로 두고 보안 패치만 이식(백포트)한다. 버전만 보는 스캐너는 이를 “취약”으로 잘못 잡는다. 매처는 finding 을 만들기 전에 두 단계로 이를 걸러낸다.

1단

OSV 버전필터

배포판 전체버전(NEVRA)으로 대조해 설치 버전에 실제 영향 없는 건을 1차 제거

→
2단

changelog 검증

통과한 건도 에이전트가 보낸 패키지 changelog 에 그 CVE 수정 기록이 있으면 취약점으로 올리지 않음

→
분리

tb_suppressed_finding

위험 집계·화면에서는 빠지되, 숨기지 않고 근거와 함께 호스트 상세에 표시(설명가능성)

에이전트는 rpm -q --changelog / dpkg changelog 에서 CVE 줄만 뽑아 함께 보낸다 — 스케줄 수집에서 기본 수집(가장 무거운 단계라 --no-changelog 로 끌 수 있음). 기존 위험 집계·화면 로직은 그대로 두고 오탐만 갈라내는 구조라 부작용이 없다.

5보안설정 점검 (CCE)

CVE(취약한 버전)가 아니라 잘못된 설정을 본다. 새로 수집하지 않고 에이전트가 이미 보낸 security/users 섹션을 src/cce.php 가 판정해 tb_cce_finding 에 저장하고 호스트 상세에 PASS/FAIL/NA 로 표시한다.

점검 항목판정 기준
SSH root 로그인 차단sshd_config PermitRootLogin
SSH 패스워드 인증 제한sshd_config PasswordAuthentication
root 외 UID 0 계정 금지/etc/passwd UID 0 계정 수
강제접근제어(SELinux/AppArmor) 활성MAC 활성 상태
호스트 방화벽 정책 존재firewalld/iptables/nftables 규칙

5개 항목 각각 PASS / FAIL / N/A 로 판정한다. 신규 수집 없이 기존 수집물을 재활용한다.

6CVE 피드 커넥터 (5종)

외부 취약점 소스를 UI 에서 설정·미리보기·스케줄(cron/매일/주기)하면 스케줄러가 당겨와 매처가 재계산한다. 매칭 자체는 검증된 소스에서 상속하고, 우리 기여는 그 위 레이어(상태·KEV/EPSS·설명가능성)에 둔다.

커넥터역할채우는 데이터
OSV.dev수집된 전 패키지를 배포판 ecosystem·버전으로 조회 → 취약점 발굴 + 조치버전cve_affected_packages · cves
CISA KEV실제 악용된 취약점 카탈로그(우선순위 가중)kev_catalog
FIRST EPSSCVE 별 악용 확률(0~1)cves.epss
NVD 2.0최근 CVE(CVSS 포함) 증분cves.cvss
KISA 보안공지국내 보안공지(해외 도구 미지원 국내 특화)advisories

7변화 추적

/changes.php 가 최근 2개 스캔의 tb_finding 를 (cve_id, package_name) 기준으로 대조해 신규 발생 · 해결됨 · 등급 상승/하락을 보여준다. 새 테이블 없이 기존 findings 비교만으로 동작한다.

8데이터 모델

수집 데이터
  • tb_host — 서버(fqdn, OS)
  • tb_scan — 수집 이력(원본 JSON 포함)
  • tb_package — 패키지(버전·소스패키지·벤더)
  • tb_exposure — 노출 소켓(포트·scope·로드)
  • tb_process — 실행 프로세스(exe·로드)
취약점 · 판정 · 계정
  • tb_cve — CVE(cvss·epss·요약)
  • tb_kev_catalog — KEV 등재
  • tb_cve_affected_package — 영향 패키지·조치버전
  • tb_finding — 판정(등급·상태·근거)
  • tb_advisory — 국내 보안공지
  • tb_feed_connector / _collection_log — 커넥터·이력
  • tb_user — 웹 계정
  • tb_activity_log — 감사로그(로그인·CRUD·ingest 기록)
오탐억제 · 설정점검 · 권한
  • tb_pkg_changelog_cve — changelog 의 CVE 수정 기록(백포트 근거)
  • tb_suppressed_finding — 백포트로 억제된 finding(근거 포함)
  • tb_cce_finding — 보안설정 점검 결과(PASS/FAIL/NA)
  • tb_role_permission — 역할×메뉴 허용 여부(설정형 RBAC)
  • tb_api_token — Export API 토큰(SHA-256 해시만 저장)

전 테이블 tb_ 접두사 통일 + 감사 4컬럼(created_at/updated_at/is_deleted/deleted_at). 삭제는 하드삭제 대신 소프트삭제(is_deleted=1, findings 등 재계산 캐시 테이블은 예외).

9배포 (agent-side push, HTTPS)

중앙이 각 호스트로 들어갈 필요 없이, 각 서버가 로컬 스케줄로 수집해 아웃바운드 HTTPS 하나로 전송. (표준 에이전트 모델)

① 중앙 서버 (내부 서버, Docker + Caddy)
./compose_runner.sh init
./compose_runner.sh prod up -d --build
Caddy 가 Let's Encrypt(DuckDNS DNS-01, 현재는 자체서명)로 TLS 를 종료하고 내부 web:80 으로 프록시 — 인바운드 80/443 개방 없이 기존 8080 포워딩 재사용. ② 각 대상 서버 (에이전트 설치 + 시간마다 자동 수집)
sudo bash install-agent.sh
  중앙 서버 주소 → https://<운영-도메인>:8080/ingest.php
  전송 토큰 → <ingest_token> · 수집 주기 → hourly
systemd-timer(우선)/cron(폴백)으로 자동 등록. 중앙 서버 자신을 스캔하는 로컬 에이전트는 루프백 평문 포트(127.0.0.1:8081)로 직접 전송(외부에서는 접근 불가). ③ 웹 — https://<운영-도메인>:8080 접속 → 서버별 취약점·상태·감사로그 확인 (<운영-도메인> 은 운영 배포 시 정해 .env.prod 의 PROD_DOMAIN 에 넣는 값)
네트워크 요건: 대상 서버 → 중앙 8080 아웃바운드만. 토큰은 <prefix>/etc/agent.env(600).

10Export API

외부 시스템(예: AI 보고서 생성기)이 스캔 결과를 가져갈 수 있도록 읽기 전용 API 를 둔다. 본체는 AI 에 묶이지 않고 결과만 넘긴다.

GET /export.php — JSON/XML, 호스트·심각도·KEV·EPSS 필터 지원
인증 헤더: X-API-Token 또는 Authorization: Bearer(Apache 가 헤더를 스트립해도 서버가 우회 처리)
토큰은 /api-tokens.php 에서 발급(웹 로그인 계정과 별도) — DB 엔 SHA-256 해시만 저장, 원문은 발급 시 1회만 표시.
상세: docs/dev/export-api.md

11권한 (설정형 RBAC)

역할은 admin / operator / user 3단계. admin 은 코드에서 항상 전체 허용(잠금 방지)이고, operator·user 는 역할 × 메뉴 허용 여부를 /permissions.php 에서 켜고 끈다 (tb_role_permission). 각 페이지는 vg_require_menu('메뉴코드') 하나로 가드한다.

13구현 현황

  • ✓ Docker(dev/prod·secrets) · 수집→전송→저장 파이프라인
  • ✓ 정밀 런타임 수집(실행중/사용중/포트 구분) · 매처 7단계 상태 판정
  • ✓ OSV 자동 매칭(전 패키지·버전필터·조치버전) · KEV/EPSS 우선순위
  • ✓ 백포트 오탐 억제(2단: 버전필터 + changelog 검증) → tb_suppressed_finding, 호스트 상세에 근거 표시
  • ✓ 보안설정 점검(CCE) — SSH·계정·MAC·방화벽 5항목 PASS/FAIL/NA(신규 수집 없음)
  • ✓ 변화 추적(changes.php) — 최근 2개 스캔 대비 신규/해결/등급변경
  • ✓ 웹(로그인·대시보드·호스트상세·취약점·변화추적·CVE상세·국내공지·자산·커넥터·사용자·권한·API토큰·감사로그) · 검색/필터·페이지네이션
  • ✓ 피드 커넥터 5종 · cron 스케줄(스케줄러 사이드카 1분마다 확인) · 배포 설치기(systemd-timer/cron, 매시간)
  • ✓ HTTPS 배포 — Caddy 리버스 프록시(Let's Encrypt DNS-01, 현재 자체서명)
  • ✓ Export API(JSON/XML) · 웹에서 발급하는 읽기전용 API 토큰(X-API-Token)
  • ✓ 설정형 RBAC(admin/operator/user × 메뉴) · 자산 관리(assets.php)
  • ✓ DB 전면 개편 — tb_ 접두사 통일 + 감사 4컬럼 + 소프트삭제 + 활동 감사로그(tb_activity_log · activity.php)
