각 서버에 경량 에이전트를 두고 설치 패키지·런타임 상태를 수집해 중앙으로 모은다. 단순 스캐너와 다른 점은 “이 취약점이 이 서버에서 실제로 위험한가”를 — 외부 노출·실행·사용 여부와 KEV/EPSS(실제 악용성)로 — 판단해 오탐을 줄이고 우선순위를 매긴다는 것. 담당자 배정·티켓·SLA 같은 조치 워크플로를 운영하는 도구가 아니라, 정확한 탐지 결과와 판정 근거를 제공하는 데 집중한다.

3런타임 상태 — 오탐 감소의 핵심

“설치=취약”으로 전부 올리지 않는다. exposures(포트) + processes(실행/로드) 를 합쳐 각 취약점을 아래 7단계로 구분하고, 실제 노출/사용 여부로 우선순위를 가른다.

상태의미기본 등급
외부노출외부(0.0.0.0) 오픈 포트로 노출 + 사용HIGH (+KEV → CRITICAL)
로컬 세그먼트 노출mDNS 등 링크로컬 멀티캐스트 — 같은 세그먼트에만 닿고 라우터를 넘지 않음MEDIUM
방화벽 차단전체 인터페이스에 리스닝하지만 방화벽이 막아 외부 도달 불가MEDIUM
로컬리스닝리스닝하지만 127.0.0.1 만MEDIUM
실행중실행 중이나 포트 미개방MEDIUM
사용중실행 프로세스가 라이브러리 로드MEDIUM
설치만아무 프로세스도 안 씀LOW
실증: 실 운영 데이터 기준 EXTERNAL(외부노출) 판정 64건 확인. 같은 openssl/glibc 취약점이 — nginx 로 외부노출된 서버에선 CRITICAL, 포트 없는 서버에선 LOW/MEDIUM 으로 갈린다. KEV(이미 악용됨) · EPSS(악용확률)로 실제 악용성까지 반영. 백포트 오탐은 OSV 버전 범위와 배포판별 수정 근거(changelog·적용 errata·벤더 OVAL/errata·Debian tracker)를 교차 확인해 억제한다(자세히는 §4).

4백포트 오탐 억제 — 버전 범위와 배포판 근거 교차 확인

배포판은 버전 번호를 그대로 두고 보안 패치만 이식(백포트)한다. 버전만 보는 스캐너는 이를 “취약”으로 잘못 잡는다. 매처는 finding 을 만들기 전에 버전 범위와 배포판별 수정 근거를 교차 확인한다.

분리

tb_suppressed_finding

위험 집계·화면에서는 빠지되, 숨기지 않고 근거와 함께 호스트 상세에 표시(설명가능성)

에이전트는 rpm -q --changelog / dpkg changelog 에서 CVE 줄만 뽑아 함께 보낸다 — 스케줄 수집에서 기본 수집(가장 무거운 단계라 --no-changelog 로 끌 수 있음). 기존 위험 집계·화면 로직은 그대로 두고 오탐만 갈라내는 구조라 부작용이 없다.

5보안설정 점검 (CCE)

CVE(취약한 버전)가 아니라 잘못된 설정을 본다. 새로 수집하지 않고 에이전트가 이미 보낸 security/users 섹션을 src/cce.php 가 판정해 tb_cce_finding 에 저장하고 호스트 상세에 PASS/FAIL/NA 로 표시한다.

계열보는 것
SSH (CCE-SSH-*)sshd -T 실효값 — root 로그인·패스워드 인증·인증 시도 횟수·X11·유휴 타임아웃 등
계정·패스워드 (CCE-ACC-* / CCE-PW-*)UID 0 중복·빈 패스워드·shadow 이전, 만료일·최소길이·품질·잠금 정책
파일 권한 (CCE-FILE-*)/etc/passwd·shadow·group·gshadow·crontab 등의 소유자·권한
시스템 (CCE-UMASK · CCE-SEC-* · CCE-SVC-* …)umask·root PATH·세션 타임아웃·SELinux/AppArmor·방화벽·레거시 서비스
시간·로그·암호화 (CCE-TIME-* / CCE-LOG-* / CCE-CRYPTO-*)시각 동기화와 오차, 로그 보존기간·원격 전송, SSH 알고리즘·디스크 암호화

현재 39개 항목을 각각 PASS / FAIL / N/A 로 판정한다(확인 못 한 항목은 PASS 가 아니라 N/A). 신규 수집 없이 기존 수집물을 재활용하고, 27개는 SSG 룰 ID 에 묶어 CIS·NIST·STIG 근거를 함께 보여준다.

9배포 (agent-side push, HTTPS)

중앙이 각 호스트로 들어갈 필요 없이, 각 서버가 로컬 스케줄로 수집해 아웃바운드 HTTPS 하나로 전송. (표준 에이전트 모델)

① 중앙 서버 (내부 서버, Docker + Caddy)
./compose_runner.sh init
./compose_runner.sh prod up -d --build
Caddy 가 Let's Encrypt(DuckDNS DNS-01, 현재는 자체서명)로 TLS 를 종료하고 내부 web:80 으로 프록시 — 인바운드 80/443 개방 없이 기존 8080 포워딩 재사용. ② 각 대상 서버 (에이전트 설치 + 호스트별 설정 주기 자동 수집)
sudo bash install-agent.sh
  중앙 서버 주소 → https://<운영-도메인>:8080/ingest.php
  전송 토큰 → 에이전트 키 화면에서 호스트별 발급 · 수집 주기 → hourly
상시 systemd 서비스가 10초마다 명령을 poll하고 설정 주기로 수집한다. systemd가 없는 환경은 cron 폴백이라 정기수집만 가능하며 즉시·예약·중단 명령은 지원하지 않는다. 중앙 서버 자신을 스캔하는 로컬 에이전트는 루프백 평문 포트(127.0.0.1:8081)로 직접 전송(외부에서는 접근 불가). ③ 웹 — https://<운영-도메인>:8080 접속 → 서버별 취약점·상태·감사로그 확인 (<운영-도메인> 은 운영 배포 시 정해 .env.prod 의 PROD_DOMAIN 에 넣는 값)
네트워크 요건: 대상 서버에서 설치 시 입력한 중앙 HTTPS 주소로의 아웃바운드만 필요합니다(현재 호환 포트 8080). 토큰은 <prefix>/etc/agent.env(600).

10Export API

외부 시스템(예: AI 보고서 생성기)이 스캔 결과를 가져갈 수 있도록 읽기 전용 API 를 둔다. 본체는 AI 에 묶이지 않고 결과만 넘긴다.

GET /export.php — JSON/XML, 호스트·심각도·KEV·EPSS 필터 지원
인증 헤더: X-API-Token 또는 Authorization: Bearer(Apache 가 헤더를 스트립해도 서버가 우회 처리)
토큰은 /api-tokens.php 에서 발급(웹 로그인 계정과 별도) — DB 엔 SHA-256 해시만 저장, 원문은 발급 시 1회만 표시.
상세: docs/dev/export-api.md

11권한 (설정형 RBAC)

역할은 admin / operator / user 3단계. admin 은 코드에서 항상 전체 허용(잠금 방지)이고, operator·user 는 역할 × 메뉴 허용 여부를 /permissions.php 에서 켜고 끈다 (tb_role_permission). 각 페이지는 vg_require_menu('메뉴코드') 하나로 가드한다.

13구현 현황

  • ✓ Docker(dev/prod·secrets) · 수집→전송→저장 파이프라인
  • ✓ 정밀 런타임 수집(실행중/사용중/포트 구분) · 매처 7단계 상태 판정
  • ✓ OSV 자동 매칭(전 패키지·버전필터·수정 버전) · KEV/EPSS 우선순위
  • ✓ 백포트 오탐 억제(OSV 버전 범위 + changelog·errata·OVAL·Debian tracker) → tb_suppressed_finding, 호스트 상세에 근거 표시
  • ✓ 보안설정 점검(CCE) — SSH·계정·파일권한·MAC/방화벽·시간·로그·암호화 39개 항목 PASS/FAIL/NA
  • ✓ 컴플라이언스(ISMS-P·ISO 27001) 자동판정 4단계(준수/판정 불가/부분준수/미준수) + 하루 1건 스냅샷 · 통제 기준 매핑(U-코드·ISMS-P·N2SF)
  • ✓ 계정 인벤토리(패스워드 해시 미수집) · 자산 중요도·N2SF 보안등급(확정값/시스템 제안값 분리)
  • ✓ 컨테이너 내부 패키지 인벤토리 · SCA(8개 언어 생태계 + 라이선스 분류) · 제거·대체 검토 권고 · 미조치 사유·승인자
  • ✓ 변화 추적(changes.php) — 최근 2개 스캔 대비 신규/해결/등급변경
  • ✓ 웹(로그인·대시보드·호스트상세·취약점·변화추적·CVE상세·국내공지·자산·커넥터·사용자·권한·API토큰·감사로그) · 검색/필터·페이지네이션
  • ✓ 고정 커넥터 11종 + 범용 API · cron 스케줄(스케줄러 사이드카 1분마다 확인) · 배포 설치기(systemd 상시 poll, 호스트별 수집 주기, cron 폴백)
  • ✓ HTTPS 배포 — Caddy 리버스 프록시(Let's Encrypt DNS-01, 현재 자체서명)
  • ✓ Export API(JSON/XML) · 웹에서 발급하는 읽기전용 API 토큰(X-API-Token)
  • ✓ 설정형 RBAC(admin/operator/user × 메뉴) · 자산 관리(assets.php)
  • ✓ DB 전면 개편 — tb_ 접두사 통일 + 감사 4컬럼 + 소프트삭제 + 활동 감사로그(tb_activity_log · activity.php)
  • ◦ (수집·저장까지만) 패키지 의존성 그래프 — 전용 화면은 아직 없다
  • ◦ (안 만든다) 알림 채널 · 조치 결재 워크플로 — 수신지·결재선이 없어 억지로 만들지 않는다(YAGNI)
